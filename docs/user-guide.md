# 使用指南

[30 秒开始阅读](../README.md#30-秒开始阅读)适合第一次打开应用；这里保留较细的订阅、阅读、配置交换和主题操作。界面命令与稳定选择器供主题或自动化开发者查看[前端命令参考](./design/frontend-command-reference.md)。

## 添加订阅与刷新

点顶栏的订阅图标（RSS 波纹）进入订阅页，输入 RSS / Atom 地址或网站首页后按 Enter 或“添加订阅”。添加和首次刷新期间会显示进行中状态；重复提交不会再启动一轮。操作期间可以输入下一个地址；成功只清除未被改动的已提交输入，失败保留输入。网站发现的候选选择与限制见下节。

顶部 **R** 同时是 Read / Home：从订阅、设置、阅读页点击时只回全局文章页；已经位于全局文章页时再次点击才执行一次“刷新全部订阅”。刷新进行中重复点击会复用当前任务。手机文章首页滚到顶部后下拉，超过阈值才触发同一刷新；普通滚动和 Reader 正文选择不应触发它。单个订阅也可在订阅页单独刷新。

手动刷新显示实际新增篇数；成功反馈约 3 秒、错误约 6 秒，详见下节。原生桌面启用了系统右键菜单；Windows 菜单的具体选项仍需实机复验，不能由 Web 验收代替。

正式 Web 登录 [`rssr-web`](./deployment/web.md) 后操作服务器上的资料库，订阅发现、抓取和自动刷新都由服务器执行。浏览器只访问同源 API，不需要远端 feed 开放浏览器 CORS；服务器的 DNS、出站策略与远端站点仍可能阻止抓取。Pages 静态演示预载构建前抓取的每日数学与陶哲轩博客文章快照，在线订阅操作不可用。

### 用网站首页添加订阅

“新增订阅”可输入网站首页。程序先尝试解析 feed，只有 HTML 才读取 head 内的 RSS/Atom 声明。一个候选自动添加；多个候选列出标题及地址，选择一个继续，或取消。修改输入会清除原候选。保存的是最终 feed 地址，网站地址优先采用 feed 自带信息，否则采用发现它的页面地址。已订阅时保留输入并提示，不刷新既有订阅。

页面没有声明时最多验证四个常见路径，无可用 feed 时保留输入并报错。添加和刷新每次响应最多 8 MiB（解压后字节及转码后的 UTF-8 文本）；单次 HTTP 请求连接最多等待 10 秒、连续 30 秒没有读到数据则停止，含正文读取的总时限为 120 秒。持续传输的慢速源可超过 30 秒；正式 Web 在服务器端执行同一流程。响应超限时报告失败，不覆盖旧文章，也不产生新增数。服务器返回发现结果与最终订阅地址。

CLI `add-feed <首页>` 使用相同发现流程；多个候选列出 URL 并非零退出，不进入交互。`--skip-refresh` 只保存验证后的订阅元信息，不导入文章。普通添加复用探测时的 feed 内容进行首次入库。

订阅名称分两种：自定义名称（CLI `--title`、OPML 或配置包导入时带的名称）和订阅源自己声明的标题。有自定义名称就显示它，刷新不会覆盖；没有时显示源标题，并随订阅源改名；两者都没有时显示订阅地址。导入文件里没有名称的订阅会清除原有的自定义名称。OPML 按其规范区分两种名称：导入时取 `text`（其他阅读器里改过的名称在这里），为空时取 `title`；导出时 `text` 写当前显示的名称（没有名称时为空），`title` 只在知道订阅源标题时写；名称里的换行、制表符原样保留，XML 不允许的控制字符在导出时去掉。其他阅读器不一定按 `text` 读名称。桌面、Android 与 Web 使用同一套 OPML 解析：文件被截断、标签没有闭合、根元素前后有多余内容、订阅不在 `<body>` 里，或属性缺少等号、引号、重复出现时整体拒绝，不导入其中一部分；这不是完整的 XML 格式校验。本应用导出的配置包写的是当前显示的名称，再导入（包括 WebDAV 下载）后这些名称都成为自定义名称，之后不再跟随订阅源改名；OPML 同样按 `text` 导入显示名称。升级到这一版之前保存的名称一律按源标题处理，下一次带标题的刷新可能把它改成订阅源的标题；需要保留的名称，升级后重新导入原来的文件即可。

### 刷新结果

手动刷新完成后显示“新增 N 篇文章”或“没有新文章”。只计算存储中新插入的文章，同键内容更新不算新增。部分订阅失败时显示成功部分的新增数和失败信息，全部失败只显示错误。全局刷新与订阅页单个订阅刷新成功提示保留约3秒、错误约6秒；期间有新操作结果时旧定时器不会清除新反馈。阅读页仍只显示 R 图标小标记，完整说明留在 live region / 按钮 title；自动刷新不弹反馈。不保存“上次新增数”。

CLI `refresh --all` 输出各成功订阅及合计的新增数，`refresh --feed-id <id>` 输出单订阅结果；失败仍以非零退出码返回。

## 查找与阅读

顶栏最右侧的左箭头可以收起整条导航，只保留左侧的右箭头；再次点击向右展开。按钮保留 44px 触控范围，手机和桌面均可使用。收起会关闭搜索框但保留搜索词，同次运行内切页保持收起状态；重启或刷新 Web 后恢复展开。需要返回、搜索、订阅或设置时先展开导航。

放大镜展开标题搜索框，窄屏或窄侧栏内会换行使用完整宽度；Enter 进入搜索结果，Esc 收起。文章页点击“全部来源”打开可搜索的多选列表，勾选后点“应用”；部分来源时入口显示“…”并提供已选数量的无障碍说明。取消或 Esc 不改变当前筛选。旁边 ✓、○、☆、★ 分别筛选已读、未读、未收藏、收藏，再次点击当前选项恢复全部。“来源／时间”切换分组方式。来源名称与未读统计同时显示在来源选择列表和订阅页，文章筛选中不提供编辑入口。标题搜索匹配字面子串，忽略大小写与全角 / 半角差异；百分号、下划线和反斜杠按普通字符处理。

筛选栏常驻，生效的筛选条件显示在其下方；没有匹配结果时会说明原因。右上“列表选项”中的“清除筛选”清除搜索、已读、收藏和来源条件并回到第一页，保留分组方式、归档显示偏好和当前订阅范围。分页按钮始终相邻排列在视口底部中央。

宽窗口的目录位于文章面板右侧，可手动收起；窄窗口通过目录按钮打开。目录日期表示当前位置和跳转目标，不会按日期过滤文章。在目录中浏览或展开／收起时可以独立寻找旧文章；重新主动滚动文章后恢复跟随。单篇正文阅读页保留原有布局。

Reader 左上角是返回按钮。阅读页可直接使用快捷键，无需先聚焦正文；`M` 切换已读，`F` 切换收藏，`←` / `K` 和 `→` / `J` 分别跳转上一篇、下一篇未读；对应方向没有未读文章时按钮禁用、快捷键不跳转。浏览同订阅的已读文章可用正文末尾的上一篇 / 下一篇同订阅文章操作。收藏与已读操作成功后更新按钮状态并向屏幕阅读器播报，不插入提示条移动正文；失败仍显示错误信息。按钮按当前显示的状态请求相反的状态，重复请求不会改动标记时间；文章已被刷新清理或订阅已删除时显示提示，不改变页面。图片可点击放大，关闭后回到原来的正文位置。标题、正文和合理的元数据使用浏览器 / WebView 原生文字选择与复制；搜索框内、输入法组词期间及带 Ctrl / Cmd 等修饰键的编辑按键不会触发阅读快捷键，也不采集阅读位置。

阅读页顶部按订阅名、作者、发布时间、“打开原文”的顺序展示。订阅名不是原文链接；缺订阅标题时用订阅 URL，无法取得订阅时显示“未知来源”并继续阅读。空作者不显示，缺发布时间显示“未知发布时间”，缺原文 URL 不显示入口。原文通过桌面系统默认浏览器、Web 新标签或 Android 系统外部链接处理器打开，不主动改变当前文章或已读状态。

阅读时间、卡片日期、年月日分组和订阅刷新时间统一使用设备本地时区，按各时间戳对应的历史规则处理夏令时；完整时间如 `2026-09-25 10:30 UTC-03:00`，零偏移或时区能力不可用时明确标注 `UTC`。存储及配置交换的时间语义不变，无额外时区设置。设备运行中切换时区后，重新加载页面可取得新的日期分组。

后台刷新可以更新本地数据，但不会把正在阅读的正文突然替换掉。正文只缓存 feed 本身提供的内容；不主动抓取原网站补全文。feed 条目没有摘要也没有正文时（例如 YouTube 频道），列表照常显示标题，阅读页提供“打开原文”。桌面和 Android 会在刷新后尽量本地化正文图片，之后只要 feed 给出的正文没有变化，本地化的结果就一直保留；Web 图片仍可能保留远端 URL。

### 本次运行内的位置记忆

返回文章列表时保留原筛选和分页，优先让刚打开的文章回到原来的屏幕位置，并轻微高亮约 2 秒。列表使用最新数据；文章已被筛掉或不在原页时，回退到有效范围内的原滚动位置。主动切换筛选或翻页仍使用原有行为。

重新打开文章或通过相邻文章按钮跳转时，保存并恢复阅读位置，包括顶部和末尾，不显示额外提示、不自动标已读。位置在点击操作、快捷键切文和前进／返回时采集，连续滚动不反复扫描正文；Android 系统返回也会先采集位置。图片迟加载时短暂校正；开始滚动后停止校正。位置只在本次运行中保存，关闭应用或刷新 Web 页面后清除，不参与配置交换。

### 多选、已读与归档

每篇文章左侧的小方框用于选择，点击标题仍打开文章。方框默认轻淡、悬停加深，选中时显示主题强调色和淡背景；图形约 16px，点击范围保持 44px，Tab＋空格可操作。顶部全选只选择当前页，显示“已选 N”；已读和归档按钮只处理明确选中的文章，未选择时禁用。

目录展开／收起、目录内滚动和同页跳转保留勾选。跨页、应用筛选、搜索或切换分组／文章视图清空勾选。保存失败保留选择供重试，成功后清空已处理项。手动归档保留文章、正文、阅读和收藏状态，与按时间自动归档共同生效；关闭自动归档不会取消手动归档。“列表选项 → 显示已归档文章”可再次查看，当前没有批量撤销入口。

CLI：`rssr-cli mark-read --all --search Rust --read-filter unread --starred-filter all --archive-filter active` 只预览；添加 `--yes` 执行。也可用 `--feed-id <id>` 替换 `--all`。归档可选 `active|all|archived`，已读可选 `all|unread|read`，收藏可选 `all|starred|unstarred`。

## 设置、主题与配置交换

点顶栏的齿轮图标进入设置。基础设置（包括浅色 / 深色 / 跟随系统）先修改草稿，点“保存设置”生效。应用内置主题或清空主题会立即提交；编辑 CSS 后需保存。Web 与桌面可导入 / 导出 CSS 文件，Android 可通过系统文件界面导出，CSS 文件导入尚未实现。想写自己的主题，先看[主题作者选择器参考](./design/theme-author-selector-reference.md)；主题只改变呈现，不负责刷新或导航逻辑。

订阅页显示订阅数、文章数、未读数、归档数。点来源右侧铅笔可修改自定义名称和 RSS / Atom URL；“使用原名”清除自定义名称。换地址仍保留该订阅的 ID、已有文章及状态；无效地址或与其他订阅重复的地址不能保存，失败时保留输入。保存地址不会立即抓取，可随后刷新订阅。JSON / OPML 导出使用显示名称，导入时将名称作为自定义名称保留；阅读、收藏和手动归档状态均不随配置交换。

已保存的主题 CSS 是当时的快照，升级不会自动覆盖。内置主题更新后，重新应用对应预设即可使用新样式；旧版内置主题仍保留原来的名称与移除入口。

配置交换支持 JSON 配置包、OPML 和 WebDAV 上传 / 下载。它用于迁移订阅和设置，不同步文章库、已读或收藏。导入配置包会替换整份配置：订阅页载入后若订阅或设置在别处被改过（另一台设备、另一个页面），导入会被拒绝、什么都不改，页面重新载入后再确认导入即可；只有订阅源自己的标题被刷新更新不算改动。WebDAV 下载在下载前记下当前配置，下载期间本地配置被改动同样会被拒绝。CLI 对应命令见 `cargo run --locked -p rssr-cli -- --help`；刷新需明确指定 `refresh --all` 或 `refresh --feed-id <id>`，两者不能同时指定。`export-config`、`export-opml`、`show-settings` 的数据写入 stdout，诊断写入 stderr，可直接重定向到文件。

需要登录的 WebDAV 服务可在设置页 Endpoint 中填 `https://用户名:密码@dav.example.com/base/`。客户端会把凭据从请求 URL 中剥离，改用 HTTP Basic；Endpoint 只保存在当前设置会话，不进入本地配置包或导出的数据。用户名或密码含 `@`、`:` 等保留字符时，按 URL 规则百分号编码。避免在截图或共享屏幕时暴露当前输入框中的凭据。

## 数据备份

Linux `/usr/bin` 安装版的数据目录是 `$XDG_DATA_HOME/rss-reader/`，未设置该变量时为 `~/.local/share/rss-reader/`。macOS 使用 `~/Library/Application Support/RSS-Reader/`；Windows 和 Linux 便携版使用可执行文件同目录的 `RSS-Reader/`。资料库 `library.sqlite3`、界面偏好与 SQLite WAL 文件都应纳入本地备份；先正常退出应用，再复制整个数据目录。正式 Web 的资料库在服务器的数据目录；清除浏览器站点数据不删除服务器文章。服务器运行时可用 `rssr-cli --data-dir <服务器数据目录> backup <新文件.sqlite3>` 备份资料库；认证库与出站策略另行保存，见 [Web 备份与恢复](./deployment/web.md#备份与恢复)。Android 卸载会清除应用沙箱内的数据库和缓存；导出配置只能保住订阅与设置，不能保住正文和阅读状态。

从 v0.1.x 升级到 v0.2：先关闭所有旧版程序（桌面端与 CLI），并保留一份完整数据目录。新版首次启动时把同一数据目录中的旧库（索引库 `rss-reader.db` 与正文库 `rss-reader-content.db`）单向导入新的 `library.sqlite3`；共用该目录的桌面端与 CLI 无论谁先启动，都从同一位置导入。macOS 的 v0.1.x 把数据放在应用包内（可执行文件旁的 `RSS-Reader/`，通常是 `RSS-Reader.app/Contents/MacOS/RSS-Reader/`），替换应用包会把它一起删除：升级前先退出旧版，把该目录中的全部文件（`rss-reader.db`、`rss-reader-content.db` 以及可能存在的 `-wal`、`-shm` 文件）复制到 `~/Library/Application Support/RSS-Reader/`，再启动新版（桌面端或 CLI 任一新版首次启动之前完成）。导入后：订阅、文章、正文、已读与收藏、设置与应用状态全部保留，自定义订阅名为空（旧版名称就是源标题）。导入先在临时文件中完成并校验，成功后才启用；失败时不会创建空库，下次启动重试。旧文件原样保留，旧版程序仍可用它们打开升级前的数据，但新版之后的修改不会写回旧文件，也不支持降级。开发版程序建立的库（含未发布的迁移 0008 / 0009）会被拒绝。旧库里不一致的数据会如实计入导入报告（日志）而不隐藏：例如 v0.1.7 升级时丢失的单库正文，这些文章导入后显示为无正文；只有之后某次刷新取得了包含该文章正文的更新响应时才会补回（订阅源回答“未修改”时不会）。只识别这两个固定文件名：旧版若用 `--database-url` 把库存成别的名字，先退出旧版并保留原件，再把副本按这两个名字放进还没有 `library.sqlite3` 的数据目录（索引库副本命名为 `rss-reader.db`，正文库副本命名为 `rss-reader-content.db`；同名的 `-wal`、`-shm` 文件一并复制并按同样方式改名，例如 `custom.db-wal` → `rss-reader.db-wal`），然后首次启动（仅指定 `--data-dir` 不会识别别的文件名）。导入一旦开始，即使启动它的程序随即退出，也会在后台完成，结果记在日志里。旧库文件必须在新版首次启动之前就位：首次启动若没找到旧库，会建立新的空资料库，之后再放入的旧文件不会被导入。v0.1.x 之间的升级规则（如 v0.1.22 自动应用 `0006` / `0007`、v0.1.21 拒绝新版迁移记录）不变。可重复的隔离验证步骤见[原生旧库升级验收](./testing/native-upgrade-verification.md)。

## 正式 Web 的恢复与升级

同一服务器的浏览器与 CLI 访问同一份资料库；这不在设备之间复制或合并文章。页面重新可见、获得焦点、重新联网、后台任务结束或操作结果未知时只读刷新。设置表单保留未保存的编辑，阅读页保留当前正文和位置；其他设备修改导致导入或批量已读的预览失效时，需要重新确认。

断线时读操作显示失败；写请求已经发出却没有可确认的结果时显示“结果未知”，不会自动重发。之后读到的新状态也不是该次操作成功的回执。切换页面不取消已接受的服务器任务；整页重新加载会丢失本页的任务 id，重新进入只读取当前数据，不恢复原任务的成功提示。

页面版本与服务器不一致时，按提示重新加载；会话失效时重新登录。离开前尝试将设置草稿（含 CSS）保留在本标签页的 `sessionStorage`，返回设置页后作为待保存编辑恢复，不自动保存。浏览器不能保留草稿时会停留并提示；离开期间又编辑但写不进时，会停止离开并清除过时的草稿。带有“草稿会丢失”的强制离开按钮由用户明确选择。

**从旧版 Web 升级到服务器模式：**旧浏览器库中的文章、已读和收藏不迁移。升级前在旧版导出 JSON 配置或 OPML，登录新版后导入订阅与设置，并重新刷新订阅。旧文章是否还能重新抓到取决于 feed 当前提供的内容；新版不会读取旧库作为离线后备。正式 Web 不再离线可读，需要服务器在线。保留旧文章前不要清除旧站点数据。

正式 Web 不要求 Web Locks 来保存资料库；本地存储仅用于设备偏好或临时草稿。`pages-demo` 演示将预抓取 RSS 载入内存 SQLite，资料库操作重新加载即重置，设备偏好单独保存；旧浏览器文章库不读取、不清除，在线订阅、WebDAV 和自动刷新禁用。详见 [Pages 边界](./deployment/github-pages.md)。

## 数学公式与复杂正文

阅读页保留正文中的 MathML 展示公式；KaTeX 同时提供 MathML 和 HTML 时只显示一份。超宽公式可横向滚动，WordPress 的 LaTeX 图片仍需原站可访问。单个公式过深、过大或文章公式总量超限时，优先显示其 TeX / 文字说明；没有可用说明时显示占位提示。异常 HTML 超出解析预算时整篇显示为纯文本，资料库保存的原始正文不变。

## 其他平台说明

单独解压的 Linux CLI 仍按便携版规则使用自身旁边的数据目录；若要操作 `.deb` 桌面端的数据，请用全局 `--data-dir`（或环境变量 `RSSR_DATA_DIR`）明确指向上述数据目录，避免误以为两个不同目录中的库会自动合并。

`v0.1.17` Linux `.deb` 已声明实际动态库依赖，发布流水线在 Ubuntu 24.04 完成了普通用户安装后两次启动和数据复用检查。若 `v0.1.16` 或更早版本曾以管理员身份在 `/usr/bin/RSS-Reader/` 产生数据，新版不会自动读取或迁移它：退出应用后先备份，管理员再将完整目录复制到新位置并改为当前用户所有。普通便携版无需迁移，仍读取原位置。其它发行版安装前请核对包内 `Depends` 是否满足。

发布包和设备验收状态见[根 README](../README.md)与[Android 构建与验收状态](./roadmaps/android-release-roadmap.md)。
