# v0.2 阶段 B2：后端契约调整（决策清单，待确认）

- 状态：已确认（2026-10-14 Develata：D1–D5、D7 按本稿方案实施；设备状态**不**移出资料库，见 D6）。第二轮设计复审的意见已按项并入（见各项“补充”）。
- 前提：B1 已把界面的全部操作收进 `rssr_api::Backend`（类型沿用现状）。B2 把它改成阶段 C 可以原样搬到 HTTP 上的契约。依据：[v0.2 架构](./v0.2-architecture.md)“架构”与“API”两节——其中已规定的（聚合读快照、标记传目标值、批量已读比较完整集合、配置替换带指纹、错误体 `{code, message, request_id}`）这里只定落实方式，不再讨论取舍。
- 每项单独提交、单独验收。B1 的界面转录作为基线保留，每项的有意变化只更新对应预期并说明；另加不做时间归一化的 JSON 契约测试和各项的并发 / 失败测试；每项都跑浏览器契约测试。

## D1 原子端口成为必需（内部整理）

配置替换与批量订阅写入的原子端口改为必需依赖，删除 `ImportExportService` 的逐步替换后备路径和 `FeedRepository` 批量写入的逐项默认实现；测试替身实现同一原子契约。（设计“存储”一节已要求。）

## D2 聚合读快照

为一次界面读取需要多次查询的用例增加 application 的聚合查询端口：文章列表（列表 + 归档计数）、阅读页快照（记录、导航、正文、订阅信息）、启动数据、订阅页快照、配置导出。原生在一次 `store.read` 内、浏览器在一次 `BrowserStore` 读取内实现；平台事务细节留在 infra，不向 application 暴露事务对象。

## D3 标记传目标值

- `set_entry_read(entry_id, read)`、`set_entry_starred(entry_id, starred)`，文章列表与阅读页共用一套输入 / 结果类型，结果返回写入后的状态并区分“本来就是”与“文章不存在”。
- 两种存储都只在状态真正变化时更新 `read_at` / `starred_at`（现在重复设置会刷新时间）。
- 不承诺“较旧请求的重试不会覆盖较新的相反操作”（目标赋值做不到，也不加版本号，与设计一致）。

## D4 设置的修改输入与配置替换的指纹

- 补充（复审）：指纹基于**原始配置投影**，不用展示模型——订阅 id、规范化地址、`generation`、原始自定义名称（不是展示名、不含源标题）、分组，以及设置；按订阅 id 排序，缺省与空值显式编码。两种存储从各自的原始字段算出同一投影，测试覆盖“自定义名称等于源标题”与“只有源标题变化”（后者不算冲突）。配置替换在同一写操作内返回所提交的设置，WebDAV 拉取与 JSON 导入不再另读一次设置。
- `update_settings(SettingsPatch) -> UserSettings`：字段全部可选，未知字段拒绝，空补丁不写入并返回当前设置，`custom_css: Some("")` 表示清空。合并、校验、保存、返回在**同一个存储写操作**内完成（新的原子端口，两种存储共用一份合并规则）。校验：取值范围；补丁含自定义 CSS 时校验这段 CSS（无关字段的修改不会因为历史 CSS 被拒；`validate_user_settings` 仍不含 CSS 校验）。
- 设置页记录基线与真正改过的字段，只提交这些字段；回包后按字段刷新未改动的部分，保留用户在保存期间的后续编辑。CLI 只提交显式给出的参数。`save_settings` 从 `Backend` 删除。
- 配置替换（JSON 导入、WebDAV 拉取）携带读取时的配置指纹：规范化的订阅身份、地址、`generation`、自定义名称、分组与设置；指纹的计算与比对共用 domain 中的一份定义，在替换的同一写事务内比对，不一致就拒绝并返回冲突。订阅页快照返回当前指纹；WebDAV 拉取的预期值在下载前取得。配置文件格式不变。

## D5 错误契约

- 协议错误体 `{ code, message, request_id }`：`code` 是稳定的字符串（`invalid_input`、`not_found`、`conflict`、`network`、`unavailable`、`storage`、`internal`；阶段 C 再加认证、版本不一致、任务状态不可用等协议层代码），`message` 是给用户看的中文，`request_id` 用于对照服务器日志（本机后端可为空）。
- 分类在错误被转成字符串之前确定：application 内部继续用 `anyhow`，`LocalBackend` 沿错误链识别 `DomainError` 等类型化原因来分类；不靠匹配文本，application 不依赖 `rssr-api`。`RefreshFlight` 合并时保留分类。
- 不只覆盖 `Err`：刷新结果里的失败原因、首次刷新失败、持久化的抓取诊断（`fetch_error`）中，凡是来自存储层的原因一律换成通用说明，原始错误链只进日志；抓取 / 解析失败的说明（网络、HTTP 状态、格式）照常显示。
- 补充（复审）：持久化的抓取诊断从此带类别（抓取、解析、存储；新列，基线未发布可直接修改）。来源不明的旧诊断（v0.1 导入、类别为空）一律视为内部文本，公开时显示通用说明，下次刷新后被新诊断取代。`StoreError` 到 `DomainError` 的转换保留忙、冲突等细分类别，分类贯穿仓储适配、刷新结果与 `RefreshFlight`，不在到达 `LocalBackend` 前丢失。
- 补充（复审）：添加订阅在激活成功、首次内容写入失败时，返回带订阅身份的“已保存、首次刷新失败”结果，而不是整体失败。
- HTTP 状态映射与破坏性操作“不自动重试”的规则在阶段 C 落实。

## D6 列表偏好与“上次打开”：留在资料库，写操作显式化

- 决定（Develata）：文章列表偏好与“上次打开的订阅”留在资料库，随资料库在所有设备间共享——单一所有者，一个人不会同时在多台设备上操作，换设备时偏好应当跟着走。不做设备侧存储与迁移。
- `bootstrap_entries` 不再在读取时顺手写“上次打开的订阅”（错误还被丢弃）；改为显式的写操作，由界面在打开订阅时调用，失败照常报告。用户看到的行为不变。
- 来源选择失效：区分“不限来源”与“限定的来源都已不存在”，后者返回空列表并提示，批量已读不会扩大到全部来源。

## D7 公开类型

- 唯一一套公开输入 / 结果类型由 application 定义；`rssr-api` 现有的三个结果类型移入 application。先定最终字段：例如阅读页快照不再暴露整份 `Entry`（去掉 `dedup_key`、`content_hash` 等内部字段）；刷新结果中的本地化任务等留在内部。
- 所有公开类型实现 `serde` 序列化与反序列化；计数为 `u64`，id 为 `i64`（客户端经 Rust 的 JSON 解析，不经 JavaScript 数值；允许范围写入协议说明）；公开类型中的每个时间字段（逐字段列清单，含可选时间与归档截止时间）用 RFC3339。配置包与浏览器存储的持久化格式不变，并用旧版真实导出的配置包做固定样本测试。
- 展示文案移出 application：`summary_line`、`display_line`、`joined_failure_lines` 由 GUI 与 CLI 各自根据结构化结果格式化；刷新失败列表带订阅 id、地址、名称与原因（无名称时用地址），保留部分成功与“订阅已保存、首次刷新失败”的区别。
- 补充（复审）：归档截止时间在共享输入校验中要求整秒（原生按 RFC3339 文本比较，非整秒会与浏览器的时间值比较不一致），预览与确认使用同一值。
- 批量已读保持现状语义：预览冻结有效查询（含归档截止时间）与完整的目标 id 集合，确认时用同一查询，在同一写事务内比较完整集合并修改；不一致返回新的预览且不写入。不改用指纹（设计要求比较完整集合）。规模上限在阶段 C 与请求体上限一并规定。

## 顺序

D1 → D2 → D3 → D4 → D5 → D6 → D7。先定事务与原子边界（D1、D2），再改写入语义（D3、D4、D6）与错误（D5），最后给最终公开类型补序列化与展示整理（D7），避免先序列化即将被替换的类型。

## 验收门禁（补充）

- 动到界面的项（D2、D4、D6、D7）在真实浏览器中按同一路径比较：视觉、交互与 Console（`docs/design/functional-design-philosophy.md` 的模块收口要求）。
- 实施前先在代码中冻结最终接口形状（公开字段、错误类型、启动数据的聚合范围——含 `bootstrap_entries` 读取的设置与订阅），再按顺序实现。

## 不在 B2 范围

- 配置包格式（D7 已说明）；application 中无人调用的公开方法清理（另列清单单独处理）。
- `HttpBackend`、服务器路由、HTTP 状态映射与重试规则（阶段 C）。
- 浏览器存储层的删除（阶段 D）；B2 期间它照常实现新契约。
