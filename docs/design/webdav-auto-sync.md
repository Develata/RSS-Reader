# WebDAV 自动同步

状态：已确认并实现（2026-11-12）。范围仍是“基础配置交换”：只同步配置包（订阅 + 设置），不涉及文章、正文、已读、收藏。整库复制另立“备份 / 恢复”入口，不在本文。

## 目标

- 设置页可以把当前 WebDAV 端点“记住并自动同步”。
- 程序启动后、首轮自动刷新完成时，按基线规则自动上传或下载一次。
- 本机保存配置后（设置、订阅增删改、导入），按同一规则上传。
- 不合并：两边都改过时不自动处理，留给用户手动选择上传或下载。

## 同步档案

每个资料库一份，保存在数据目录的 `remote-sync.json`（Unix 下 0600，临时文件 + 改名原子写入）：

- 端点（含 userinfo 凭据，明文；2026-11-12 Develata 决定先用明文，钥匙串以后再议）与远端路径；
- 基线：上次成功同步时的本机配置指纹（`ConfigFingerprint`）与远端内容哈希；
- 最近一次自动或手动同步的结果（时间、触发方式、结论）。

档案不进 `library.sqlite3`，也不进配置包：备份、导出、上传配置都不会带出密码。设置页只回传去掉密码的端点。停用自动同步即删除档案。

服务器（`rssr-web`）的档案在 `RSSR_DATA_DIR`，与 `auth.sqlite3` 同等对待；浏览器不保存凭据。Pages 演示没有档案，也不能联网。

## 基线规则

两类哈希：

- 本机指纹 `ConfigFingerprint`：按本地订阅 id 计算，只在本机比较；源标题被刷新改名不算改动。
- 远端内容哈希：配置包按订阅地址排序后，对订阅与设置做 SHA-256，忽略 `exported_at`；可以跨设备比较。

一次同步：先读本机指纹，再下载远端（同时取 ETag），再判断：

| 情况 | 动作 |
| --- | --- |
| 远端不存在 | 上传（`If-None-Match: *`） |
| 本机导出内容与远端相同 | 不传输，记基线 |
| 没有基线、两边内容不同 | 不动，提示首次同步需手动选择方向 |
| 只有远端变了 | 下载（沿用指纹防并发的整份替换） |
| 只有本机变了 | 上传（有 ETag 时带 `If-Match`，被拒视为冲突） |
| 两边都变了 | 不动，提示手动选择 |
| 两边都没变 | 不动 |

成功后基线更新为：上传时 =（上传前读到的本机指纹，上传内容的哈希）；下载时 =（替换事务内算出的新指纹，远端哈希）。先读指纹后导出，期间的本机改动最多导致下次多传一次，不会丢。

手动上传 / 下载（使用已保存档案时）不比较基线、不带条件头，成功后同样更新基线；这是解决冲突的方式。未保存档案时手动操作照旧，不碰基线。

## 触发

- **启动**：随自动刷新启动（`ensure_auto_refresh_started`），首轮刷新结束后执行一次。桌面 / Android 为程序启动；`rssr-web` 为服务进程启动，不是浏览器登录。CLI 不自动同步。
- **保存后**：配置可能改变的操作成功后，防抖数秒再同步一次；本机指纹与基线相同则不联网。没有基线时不自动上传。
- 同一资料库的同步串行执行，与手动上传 / 下载互斥。
- 失败（多为离线）只记录结果并显示一条状态提示，不重试、不阻塞启动。

## 界面

- 设置页 WebDAV 卡片：未记住时同现在，另加“记住并自动同步”；记住后显示端点（无密码）、远端路径、最近结果，上传 / 下载使用档案，另有“停用自动同步”。
- 原生 GUI 启动同步结束后：下载了配置则重读页面并提示；冲突或失败给一条状态提示；上传或无变化不提示。正式 Web 不在页面加载时提示（启动属于服务器），结果见设置页。

## 不做

- 合并订阅列表、按字段合并设置。
- 定时轮询远端。
- 系统钥匙串（以后可以替换档案的凭据存放方式，接口不变）。
