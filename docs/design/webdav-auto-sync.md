# WebDAV 自动同步

状态：已确认并实现（2026-11-12）。范围仍是“基础配置交换”：只同步配置包（订阅 + 设置），不涉及文章、正文、已读、收藏。整库复制另立“备份 / 恢复”入口，不在本文。

## 目标

- 设置页可以把当前 WebDAV 端点“记住并自动同步”。
- 程序启动后、首轮自动刷新完成时，按基线规则自动上传或下载一次。
- 本机保存配置后（设置、订阅增删改、导入），按同一规则上传。
- 不合并：两边都改过时不自动处理，留给用户手动选择上传或下载。

## 同步档案

每个资料库一份，保存在数据目录的 `remote-sync.json`（Unix 下 0600，临时文件 + 改名原子写入）：

- 端点与远端路径（远端文件固定为端点文件夹里的 `rss-reader.json`，2026-11-13 Develata 决定去掉 Remote Path 栏；CLI 的 `remote_path` 参数默认同名）；凭据只来自设置页的用户名、密码两栏（2026-11-13 Develata 决定只保留这一种填法，Endpoint 带凭据即拒绝），按“字母数字以外全部百分号编码”写进端点的 userinfo 保存（明文；2026-11-12 Develata 决定先用明文，钥匙串以后再议）；
- 基线：上次成功同步时的本机配置指纹（`ConfigFingerprint`）与远端内容哈希；
- 最近一次自动或手动同步的结果（时间、触发方式、结论）。

档案不进 `library.sqlite3`，也不进配置包：备份、导出、上传配置都不会带出密码。设置页只回传去掉密码的端点；含端点的类型的 `Debug` 输出也去掉密码。停用自动同步即删除档案；档案无法读取时，设置页说明原因并仍可停用。

服务器（`rssr-web`）的档案在 `RSSR_DATA_DIR`，与 `auth.sqlite3` 同等对待；浏览器不保存凭据。Pages 演示没有档案，也不能联网。

## 基线规则

两类哈希：

- 本机指纹 `ConfigFingerprint`：按本地订阅 id 计算，只在本机比较；源标题被刷新改名不算改动。
- 远端内容哈希：配置包按订阅地址排序后，对订阅与设置做 SHA-256，忽略 `exported_at`；可以跨设备比较。

一次同步：先下载远端（同时取强 ETag），再在同一个读快照里导出本机配置并取其指纹，再判断（修改后触发的同步先单独读一次指纹，与基线相同就不联网）：

| 情况 | 动作 |
| --- | --- |
| 远端不存在 | 上传（`If-None-Match: *`） |
| 本机导出内容与远端相同 | 不传输，记基线 |
| 没有基线、两边内容不同 | 不动，提示首次同步需手动选择方向 |
| 只有远端变了 | 下载（沿用指纹防并发的整份替换） |
| 只有本机变了 | 上传（有强 ETag 时带 `If-Match`，412 视为冲突；没有强 ETag 时无条件上传） |
| 两边都变了 | 不动，提示手动选择 |
| 两边都没变 | 不动 |

成功后基线更新为：上传时 =（导出时同一快照的指纹，上传内容的哈希）；下载时 =（替换事务内算出的新指纹，远端哈希）。基线的两半总是描述同一份配置，传输期间的本机修改（包括改了又改回）在下次同步时仍算作改动。下载时若本机在快照之后又改过，替换被拒，记为冲突。

基线写不进档案时，这次结果保持原样（下载了仍是下载，界面照常重读），另标“未能保存”，由后端在内存里保留到下次写入成功，设置页与启动提示都会显示；手动操作返回错误而不是成功。启动同步的等待由守卫结束：首轮刷新即使异常终止，也不会一直显示“同步中”。

手动上传 / 下载（使用已保存档案时）不比较基线、不带条件头，成功后同样更新基线；这是解决冲突的方式。请求带上页面看到的端点与路径（不含密码），保存的档案已换成别的端点时拒绝，避免确认的是 A、执行的是 B。未保存档案时手动操作照旧，不碰基线。

### 已知限制

- 服务器不给强 ETag（或代理压缩后变成弱 ETag）时，从读取远端版本到上传提交之间（每个请求最长 30 秒，加上本机处理），另一设备的上传可能被覆盖。客户端不解压，并对每个请求声明 `Accept-Encoding: identity`，以免压缩削弱 ETag。是否在没有强 ETag 时停用自动上传，留待真实网盘验收后决定。
- 串行只在同一进程内：同一数据目录同时运行两个带档案的进程（例如桌面端与服务器共用数据目录）不受支持。

## 触发

- **启动**：随自动刷新启动（`ensure_auto_refresh_started`），首轮刷新结束后执行一次。桌面 / Android 为程序启动；`rssr-web` 为服务进程启动，不是浏览器登录。CLI 不自动同步。
- **保存后**：配置可能改变的操作成功后，防抖数秒再同步一次；本机指纹与基线相同则不联网。没有基线时不自动上传。
- 同一后端内，自动同步、手动上传 / 下载（含未保存端点的）、保存与停用档案经同一把锁串行。
- 失败（多为离线）只记录结果并显示一条状态提示，不重试、不阻塞启动。

## 界面

- 设置页 WebDAV 卡片：未记住时同现在，另加“记住并自动同步”；记住后显示端点（无密码）、远端路径、最近结果，上传 / 下载使用档案，另有“停用自动同步”。
- 保存 / 停用一次只处理一个；每次读取或写入都使更早发出的读取作废，只有最新请求的结果更新卡片。读到同步正在进行（已排队或执行中）时，页面每 2 秒再读一次（同时只有一个后续读取），直到结果写入；页面保存设置后也读一次。
- “同步中”从排队开始，到取得同步锁之后才清除排队标记，中间不会出现假空闲。
- 原生 GUI 启动同步结束后：下载了配置则重读页面并提示；冲突或失败给一条状态提示；上传或无变化不提示。正式 Web 不在页面加载时提示（启动属于服务器），结果见设置页。

## 不做

- 合并订阅列表、按字段合并设置。
- 定时轮询远端。
- 系统钥匙串（以后可以替换档案的凭据存放方式，接口不变）。
