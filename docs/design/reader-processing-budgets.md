# 正文解析与图片后台处理预算

核对日期：2026-10-28。适用于正文共享处理链路和原生宿主（桌面、Android、CLI、服务器）；浏览器正文使用同一 HTML 处理代码，图片缓存工作由原生宿主负责。本轮实现与实测见[交接](../handoffs/2026-10-28-parse-image-performance.md)。

## 正文解析

正文先做显示规范化，再经过 `html::parse_budget` 的骨架预解析，预算内才交给 ammonia 清洗。超预算时整篇改为转义的纯文本段落；公式自身另有降级预算。不得通过关闭消毒或扩大超时掩盖解析成本。

- `vendor/html5ever` 基于锁定的 0.39.0，只在两个源文件加补丁，来源、上游问题和移除条件见 [RSSR-PATCH.md](../../vendor/html5ever/RSSR-PATCH.md)。每个标签少于 16 个属性时保留向量查重，大标签使用临时索引；保持顺序、首个值优先、重复报错和标签间状态清理。纯文本降级、预算预解析和 ammonia 共用这个版本。
- 预算按完整活动格式化表长度计费，包括没有 DOM 句柄的 Marker。清点操作自身也计入预算。新增的观察接口不改变树构建行为。
- 格式化开始标签进入树构建之前先检查 Noah's Ark 的预计费用；费用仍由原骨架 sink 记账，不重复扣费。`TokenSink` 包装层保留原分词状态、raw text、外来内容和 EOF 行为。
- 块级工作量预算仍属于纵深防御，不能证明任意 HTML 全链路线性；单个 token 的树构建尚不能中途取消。继续保留深层公式、普通长文、文本转义和恶意形状回归。
- 图片地址规范化中，无引号属性值里的 `/` 是 URL 内容。只有位于属性之间且紧邻 `>` 的 `/` 才是自闭合标记；`src=/directory/` 的尾部斜杠必须保留。

## 候选与正文身份

`rssr-application::RefreshLocalizationCandidate` 只保留 generation、文章去重键、源 URL、源内容哈希和 HTML 指纹，不复制 HTML、纯文本或标题。暂时仍为当前刷新中所有含 HTML 的文章产生候选：只保留新增/变更文章会丢掉未成功图片的重试机会。

持久的 `rssr-content-v2` 哈希由 `content_identity` 单点定义，字节格式保持不变：前缀、title/text/html/url 顺序、存在标记、小端字节长度。它包含相对图片地址所依赖的源 URL；只比较 HTML 指纹会漏掉“正文不变但 URL 改变”的陈旧任务。

取得后台执行名额后，宿主才逐篇从共享仓储读取正文，读取时检查订阅仍活跃、generation 相同及 HTML 字节上限。再同时检查源内容哈希和 HTML 指纹；已经派生或已经变化的正文不发请求。写回继续比较 generation、存储内容哈希（`IS`）以及读到的精确正文，防止覆盖新刷新或先完成的阅读页图片缓存。没有新迁移，也没有第二套文章状态。

## 后台调度

`local_backend::native_host` 只负责组合能力。`image_localization` 负责读正文、调用图片处理和有条件写回；其 `background` 子模块只负责准入、轮转和释放。仓储不包含网络或调度策略。

| 限制 | 当前值与含义 |
| --- | --- |
| 执行并发 | 每个宿主实例最多 2 个订阅 |
| 单轮网络尝试 | 最多 5 篇；发起图片请求即计数，失败和超时也计数 |
| 单轮执行时长 | 取得名额后最多 180 秒；不包含等待名额时间 |
| 单个排队任务 | 最多 256 个候选、256 KiB 计费载荷 |
| 全局排队与执行占位 | 最多 64 个订阅、8 MiB 候选计费载荷；同订阅不叠加 |
| 轮转记录 | 最多 256 个订阅，固定大小去重键指纹；与 generation 绑定 |
| 原有图片限制 | 后台 768 KiB HTML、16 张图片、单图 3 MiB、总图 6 MiB、请求 8 秒；阅读按需使用原有较宽预算 |

候选载荷计费包括已准入任务的新向量容量、字符串容量及 URL 文本，不是进程总内存上限；刷新结果中的临时候选、源模型、活跃正文、下载结果、解析结构及分配器开销不包含在此数字中。新建容量受限的向量，不能只截短原向量后继续保留整批容量。

每检查一篇就前移游标，发生在异步读取/下载之前；无图、已派生、陈旧正文也推进。下一次可入队的刷新从上次位置之后开始并轮转，稳定候选列表中的失败前五篇不会一直挡住第六篇。任务取消或超时后释放占位和字节计数，保留已推进的游标；失败不写“成功”状态，未来仍可重试。

这是有界、尽力的后台优化，不承诺跨进程全局公平性或持久续排：

- 队列饱和、同订阅已有任务、过大候选被跳过时，等待下次可入队的更新刷新或阅读按需处理；队列总量约束不等于所有订阅都能在本轮被处理。
- 游标淘汰、应用重启或 generation 变化可从头重试；源列表删掉游标所指文章时也从当前列表开头开始。
- 304 不携带新候选，本轮没有新增 304 后自主续排或持久重试队列。只收到 304 时，未轮到的文章仍可通过打开阅读页触发按需处理。

## 验证入口

- 解析：`html::parse_budget`、`test_reader_tokenizer`、`test_reader_html_stress`、真实浏览器的 `wasm_reader_html_contract_harness`。
- 图片：`local_backend::image_localization` 的本地 HTTP + 内存 SQL 测试，覆盖前五篇失败/第六篇成功、取消、候选限额、源更新、URL 单独更新、阅读派生先完成、删除后恢复。
- 性能：release `reader_html_probe`，再运行 `scripts/measure_reader_html.ps1`。固定形状各独立进程三次，记录输入/输出哈希、完整正文处理耗时与 Windows OS 峰值工作集。当前 runner 不会自动终止超时进程，只用于这些有输入上限的确定夹具，不作为不可信任意输入的 fuzz runner。
- 当前数据：[2026-10-28 实测](../testing/evidence/2026-10-28-parse-image/README.md)。历史 418 篇语料结果没有在本轮重新执行，不能替代当前覆盖。
