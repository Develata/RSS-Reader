# v0.2 阶段 C：服务器端 Web（实施计划，待确认）

依据：[v0.2 架构](./v0.2-architecture.md)（目标 1、API、安全与运行、阶段与门禁）。本文把阶段 C 拆成可独立验收的工作项，写明现状、做法与需要确认的决定。决定确认前不开工：工作项都涉及公开协议、认证或出站访问边界。

## 现状（2026-10-15 调查）

- `rssr-web` 只是静态包托管加登录：
  - 认证：用户名与 Argon2 哈希来自环境变量。会话 cookie 是 HMAC 签名的“用户名:到期时间”，服务器不保存会话，退出登录无法吊销已复制的令牌。默认 12 小时。
  - 退出登录是 `GET /logout`；没有 CSRF 与 Origin 校验。
  - 登录有失败限速。
  - `/__codex/*` 冒烟辅助路由在开启时会给任何人发会话 cookie（默认关闭）。
- 资料库在每个访客的浏览器 `localStorage` 里；`/feed-proxy` 代抓 feed 以绕过 CORS。
- 出站访问：只有 `/feed-proxy` 拦截内网、回环、链路本地、保留地址，并固定 DNS 结果、逐跳复核重定向。infra 里的 feed 抓取、订阅发现、图片本地化、WebDAV 都没有地址检查（适合桌面，不适合服务器）。
- `Backend` 只有 `LocalBackend` 一个实现（25 个方法），公开类型已可序列化（B2-D7）。
- 本地化的图片以 `data:` URI 写进正文 HTML 存在库里，服务器端可以照搬原生做法。

## 工作项

### C1 出站访问策略（infra）

把 `/feed-proxy` 的地址策略移到 `rssr-infra`，成为所有出站请求（feed 抓取、订阅发现、图片本地化、WebDAV）共用的一层：
- 只允许 http/https；
- 解析后检查每个地址，固定 DNS 结果，重定向逐跳复核；
- 保留现有的体积与时限上限。

策略有两种：
- `Unrestricted`：桌面、Android 与普通 CLI 用，保持现状，可访问内网。
- `PublicOnly { allow }`：服务器用，只允许公网地址，管理员可显式放行地址段或主机名。

同一数据目录上的 CLI 必须执行与服务器相同的策略，策略的来源见决定 Q3。`/feed-proxy` 随 C4 删除。

### C2 认证（`auth.sqlite3`）

- 认证数据单独存放在数据目录的 `auth.sqlite3`，不在资料库里，备份资料库时不包含：
  - 所有者凭据：Argon2 哈希；
  - 会话：不透明令牌，库里只存摘要，带创建、最后使用与到期时间；
  - CSRF 令牌：与会话绑定。
- 改密码撤销全部会话；提供“退出所有设备”。
- Cookie 带 `Secure`、`HttpOnly`、`SameSite=Lax`。退出登录改为受保护的 `POST`。
- 写请求要求精确匹配的 `Origin`，并带自定义请求头与 CSRF 令牌。
- 未登录访问 `/api` 返回 JSON 401；`/api` 不落入 SPA 回退。
- 保留现有登录限速。
- 删除 `/__codex/*` 冒烟路由：发会话 cookie 的测试入口不留在正式程序里，冒烟改为测试代码内搭建。

### C3 API（`/api/v1`）与后台任务

- 每个 `Backend` 方法对应一个路由，请求与结果直接用 application 的公开类型（JSON），错误体为 `{ code, message, request_id }`。
- 路由、协议版本与错误体定义在 `rssr-api`，服务器与客户端共用。
- 长操作走有界的内存后台任务：`202` 返回任务 id，客户端轮询 `/api/v1/jobs/{id}`。
  - 任务状态与业务结果分开：任务失败时也可能已有部分订阅提交成功。
  - 服务器重启或结果过期后，轮询明确返回“状态不可用”。
  - 范围见决定 Q2。
- 破坏性操作（配置替换、OPML 导入、删除订阅、批量已读提交）：客户端不自动重试；回包丢失时显示“结果未知”，然后重新读取状态。
- 网页包与服务器同版本：请求带客户端版本；不一致时服务器拒绝写入，页面提示重新加载，并保留正在编辑的内容。
- 请求体、导入大小、查询规模与并发都有上限。

### C4 网页端改用服务器（`HttpBackend`）

- `rssr-app` 新增 `HttpBackend`，用 HTTP 实现 `Backend`。正式 Web 构建启动时选它；演示站构建（`pages-demo`）在阶段 D 之前继续使用浏览器存储。
- 页面代码不区分两种后端。
- 正式 Web 构建删除：浏览器存储后端、本地浏览器门禁（`localStorage` 里的本地口令）、`/feed-proxy` 回退。依赖图门禁继续保证正式 Web 不含 SQLite。
- 自动刷新改由服务器负责，页面不再运行刷新循环；其他设备的修改在页面聚焦、任务完成或重新连接后重新读取。

### C5 服务器运行

- `rssr-web` 打开数据目录（`--data-dir` / `RSSR_DATA_DIR`，容器内 `/data`）里的 `library.sqlite3`，经 `LocalBackend` 调用用例。服务器端的 host 与原生端相同（含图片本地化），出站策略为 `PublicOnly`。
- 唯一的定时刷新任务：不依赖浏览器在线，每轮重新读取设置（CLI 可能改过）。
- 备份：`rssr-cli backup <文件>`，用 `VACUUM INTO` 生成一致的副本，不含认证文件。恢复步骤写入部署文档：停止写入者、替换文件、清空会话。

### C6 部署与迁移

- Compose 与部署文档改为数据卷 `/data`，内含 `library.sqlite3` 与 `auth.sqlite3`。
- 从旧版 Web 升级：架构已确定断代，只能在旧版页面导出配置 JSON，升级后导入；文章不迁移。文档写明。

## 提交顺序与验收

1. C1 出站策略。单元测试覆盖各类地址、DNS 固定与重定向复核，CLI 与服务器共用。
2. C2 认证。测试覆盖会话吊销、CSRF / Origin 拒绝、401 JSON、登录限速。
3. C3 + C5 的服务器部分。API 契约测试对每个路由与 `LocalBackend` 的结果做对照；任务状态与重启语义。
4. C4 网页端切换。特征测试，wasm 检查，依赖图门禁。
5. C6 文档与 Compose。

阶段门禁（架构文档）：
- 两个浏览器加 CLI 共用一个资料库；
- 提交后断线与重试；
- 配置指纹冲突；
- 重启；
- 备份与恢复；
- 认证、CSRF、SSRF；
- 真实界面验收；
- 独立评审。

## 需要确认的决定

- **Q1 所有者凭据的初始化与旧部署迁移**
  - 建议：首次启动时，若 `auth.sqlite3` 不存在，用现有的 `RSS_READER_WEB_USERNAME` 与 `RSS_READER_WEB_PASSWORD_HASH`（或首次启动用的 `RSS_READER_WEB_PASSWORD`）建立凭据，此后以库里的为准；改密码用 `rssr-web passwd`（从标准输入读）。旧部署升级时不用改环境变量。
  - 备选：只用命令行初始化，不读环境变量。
- **Q2 哪些操作走后台任务**
  - 建议：刷新全部、刷新单个订阅、添加订阅（含首次刷新）、WebDAV 上传与下载走后台任务；配置 JSON 与 OPML 导入同步执行（单次事务、有大小上限，通常很快）；阅读页的图片本地化同步执行、带时限。
  - 备选：凡涉及网络的都走后台任务（包括导入后的首次刷新）。
- **Q3 同一数据目录上的 CLI 如何执行服务器的出站策略**
  - 建议：数据目录里放一个策略文件（例如 `outbound.json`，由管理员或首次启动的服务器写入）。存在时，服务器与 CLI 都按它执行 `PublicOnly` 与放行列表；不存在时为 `Unrestricted`（桌面与普通 CLI 的现状）。
  - 备选：CLI 加 `--public-only` 参数或环境变量，由管理员在服务器上自行设置。缺点是容易漏设。
- **Q4 会话有效期**
  - 建议：空闲 30 天过期、绝对 90 天过期，使用时续期；可随时“退出所有设备”，改密码全部吊销。单一所有者、个人设备，长会话更实用。
  - 备选：保持现在的 12 小时。
