# Windows / Android 阅读基线，2026-10-25

本轮完成当前阅读分支的独立验证，不做 v0.2 主线集成。结果没有显示整体性能改善；当前包内存略高，Android 清除搜索恢复列表也较慢。新增文章级目录与 Rust 模块化等同时存在，不能把差异单独归因于 Rust 化。

- Windows：i7-12700H、RTX 3060 Laptop、Windows 11 build 26200、2560×1440 / 200 Hz 屏幕。

- 每个平台按 A、B、B、A、A、B 测量，各 3 个冷进程。5000 篇文章、6 个来源，长正文 120 段和 4 张本地图片；每页 50 篇。
- 每轮搜索单篇、清除搜索、展开来源各 5 次；Windows 阅读往返 5 次，Android 阅读往返 1 次。旧 Android A 的第二次返回确有缺陷，因此两版均限定为每个冷进程一次往返，另行验收 B 的连续返回。
- 内存每状态静置 4 秒后取 3 次。以下表格为“三次采样的中位数，再取三轮中位数”；耗时同理。Android 阅读往返每轮只有一个样本。没有做显著性检验。
- Windows 与 Android 的持久化位置、文章 ID、日期分布及测试标记不同，只做各自平台 A/B 对照。Android 原刷新设置保留，固定本地 feed 服务可用；启动包含原有刷新工作，不是关闭后台任务后的纯渲染测试。
- 汇总脚本执行被自动审批拒绝，未改用其他执行器。下列数字直接核对已完成的原始记录，属于人工汇总；未产生或声称通过自动汇总 JSON。

## 解释与后续优先级

1. 已确认并修复 Android 连续返回缺陷：WebView 点击和异步释放发生在不同线程，thread_local 防重入标记无法正确复位。B 实机连续 5 次按钮返回及 3 次系统返回通过，位置恢复未丢失。
2. 新目录增加文章标题节点。Windows 目录由 0 增至 585 个文章叶节点，Android 为 597；Android 目录节点由 72 增至 1338。它是后续减少隐藏或过长目录渲染负载的候选，当前没有做单因素对照，不能声称已证明内存增量来源。
3. 优先解决迁移 SQL 换行导致的历史数据库兼容风险，再考虑受控的目录渲染优化。不能直接统一为 LF 后就宣布兼容，已有混合换行构建生成的库也需要升级路径。
4. v0.2 主线集成独立规划，当前分支与主线大幅分叉；本轮 CI 和基线不等于可直接合并或可发布。
