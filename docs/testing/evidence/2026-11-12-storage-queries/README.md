# 文章列表、计数与订阅摘要的查询计划证据

日期：2026-11-12。基线 `origin/main` = `7d60a59c`（资料库 schema 与 v0.2.3 相同）；改动见分支 `claude/storage-linear-queries` 与[交接](../../../handoffs/2026-11-12-storage-linear-queries.md)。

## 结论

未限订阅的文章列表、列表旁的归档计数、订阅页的未读 / 总数，原先都会逐行读全部文章，耗时随文章总数线性增长。改动后前者沿排序索引只读一页，后两者只读新覆盖索引。在 25 万篇文章的库上，默认首页列表从 34.6 ms 降到 3.2 ms，归档计数从 195.1 ms 降到 8.0 ms，订阅摘要从 199.4 ms 降到 8.2 ms。全部 270 种列表形状与 270 种计数形状的结果与改动前逐行一致。计划变化带来的退化只有 9 种，绝对值都在 6 ms 以内，见“退化”。

## 方法

- 夹具：[make_fixture.py](./make_fixture.py) 用仓库迁移 0001、0002 建库，200 个订阅（5 个已删除），5 万 / 25 万篇文章；标题、URL、作者和约 400 字摘要按真实行宽填充；10% 未读、2% 收藏、3% 手动归档、5% 无发布时间，时间分布约 6 年。与应用一致，不跑 `ANALYZE`。
- 带索引的副本：复制夹具后执行 `CREATE INDEX cand_w ON entries(feed_id, is_read, is_starred, is_archived, published_at)`，定义与迁移 0003 的 `idx_entries_feed_flags` 相同。
- 对比：[final.py](./final.py) 把 `store/entries.rs`、`store/feeds.rs` 的 SQL 原样拼出两版（当前 main / 本改动），覆盖读 × 收藏 × 归档 × 范围（全部、单订阅、30 个订阅）× 标题搜索的全部组合；列表带 `LIMIT 2001`。每个形状两版交替运行取 5 次最小值，并断言两版返回完全相同。`listed_title` 用 Python 截断函数代替。
- 环境：Python 3.13 自带 SQLite 3.53.1；应用捆绑 3.53.2。`store::query_plans` 单元测试在捆绑版本上确认了下文依赖的计划。原始输出见 [final-output.txt](./final-output.txt)。

## 退化

25 万篇时，对第一轮慢于 1 ms 的形状逐个复测并比较计划（[复测输出](./recheck-slower-250k.txt)）。计划没变的差值在复测中消失，属于噪声；计划变了且复测仍慢的如下：

- 列表 2 种：未限订阅的标题搜索（只看手动归档 189.0 → 192.4 ms，隐藏自动归档 194.3 → 198.0 ms），约 +2%。搜索本来就逐行比对标题。
- 计数 7 种：主要是“只看收藏”的计数。原先走收藏索引只读 2% 的行，现在逐个订阅扫描覆盖索引，例如隐藏自动归档时 0.4 → 4.2 ms，加搜索时 3.9 → 9.5 ms；另一种是“不看收藏 + 搜索”24.6 → 27.9 ms。最大绝对增量 5.9 ms，而同一批改动让默认计数省下约 187 ms。

## 选择过程中排除的写法

- 全部语句都从 `entries` 出发：多订阅范围的列表在 25 万篇时慢 24–33 ms，且已读筛选的计数仍要读行（约 175 ms）。
- 只加索引、`OnlyArchived` 仍写成 `OR`：规划器把它拆成多索引并集，已读 / 未读 + 不看收藏 + 多订阅的归档视图慢 30–50 ms。改成 `ExcludeArchived` 的否定后不再出现。
- 只加 `(feed_id, is_read)`：未限订阅的默认列表会改用它，慢到 39 ms。

## 代价

- 写入（25 万篇，事务内回滚测量）：刷新式 upsert 120 行 11.8 → 12.4 ms；一次把 2000 篇标为已读 30.9 → 44.6 ms。
- 升级：25 万篇建索引约 0.4 秒；库文件 293.5 → 301.9 MB（+2.9%）。
- 其他 `entries` 语句（阅读导航、批量已读 / 归档、刷新、删除、图片本地化）的计划只有两条变化，都变快：单订阅全部标为已读 30.4 → 5.9 ms，其预览 25.9 → 0.03 ms。

## 噪声与未覆盖

- 25 万篇时一个“单订阅 + 已读 + 收藏 + 搜索”列表首轮记为 +25.6 ms；两版计划相同，复测 9 次中位数 185.5 / 186.3 ms，判定为噪声。
- 仍存在、不在本次范围：单订阅的“已读”列表走全局未读索引，25 万篇约 177 ms（两版相同）；标题搜索是 `instr` 全扫。
- 没有在 wasm（Pages 演示的 sqlite-wasm）上计时；那里数据量只有预抓取的几百篇。
