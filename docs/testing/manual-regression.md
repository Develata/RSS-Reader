# 手工回归测试清单

这份清单当前主要服务于 Web 端回归，也可作为 desktop 端交互回归的参考基线。
建议在这些场景下使用：

- 阅读页、订阅页、设置页有明显改动之后
- 主题系统或自定义 CSS 能力调整之后
- 发版前做一轮基础人工验收时

## Web 回归清单

1. 默认入口与路由
- 打开 `/`
- 确认默认进入“文章”页
- 点击 `订阅 / 文章 / 设置`
- 确认页面切换正常，没有白屏或卡死
- 浏览器刷新后，当前页面还能正常重新进入

2. 订阅管理
- 在“订阅”页添加一个有效 RSS URL
- 确认订阅列表出现该 feed
- 点一次 `刷新全部`
- 如果某个 feed 行有 `刷新此订阅`，也点一次
- 如果有 `删除订阅`，测试两步确认删除是否正常

3. 文章列表与阅读
- 进入“文章”页
- 确认能看到文章列表
- 点开一篇文章进入阅读页
- 确认标题、来源、时间、正文都正常
- 返回文章页后列表仍正常

4. 状态操作
- 点一次 `标记已读`
- 点一次 `收藏`
- 开关 `仅未读`
- 开关 `仅收藏`
- 输入标题关键词搜索
- 刷新页面后确认这些状态仍能正确显示

5. 主题切换
- 去“设置”页
- 用主题下拉选择一个预置主题，点 `应用所选主题`
- 确认页面样式立刻变化
- 用主题卡片点一次 `应用这套主题`
- 再点当前主题卡片的 `移除这套主题`
- 确认只移除了当前主题，不是异常清空别的内容
- 点 `导出当前 CSS`，确认能导出
- 如方便，再点 `导入主题文件` 导回一份 CSS
- 桌面端悬停长来源名，确认 `title` 可查看完整名称；移动端只验收截断与可访问名称，不假定长按一定显示浏览器 tooltip

6. Android 主题导出（SAF）
- 在 Android 设置页应用一套主题后点 `导出当前 CSS`
- 在系统保存器中取消，确认页面显示已取消且不报错
- 再次导出并保存，确认文件字节与当前 CSS 完全一致
- 保存器显示期间再次触发导出应被拒绝，不覆盖已有在途请求
- 使用拒绝写入或返回空输出流的测试 provider，确认页面报告错误且应用不崩溃
- 确认生成 manifest 不含存储权限；Android 主题文件导入仍是已知未实现项

7. 设置持久化
- 在“设置”页改一个普通设置，比如主题模式、刷新间隔或字号
- 点 `保存设置`
- 浏览器刷新
- 确认设置仍保留

8. 配置交换
- 到“订阅”页测试：
- `导出配置`
- `导出 OPML`
- 如方便，再做一次 `导入配置` 或 `导入 OPML`
- 确认没有报错，列表状态正常

9. Web 持久化
- 关闭当前标签页
- 重新打开服务地址
- 确认订阅、设置、自定义 CSS 仍在
- 这一步是 Web 端最关键的本地持久化检查

10. Android safe-area（API 35+ debug 预演）
- 记录系统 WebView 版本；应至少为 136
- 分别覆盖浅色/深色、竖屏/横屏、手势导航/三键导航，以及 IME 展开
- 确认顶部导航、导航展开按钮、桌面目录 rail、Atlas sidebar 和 reader bottom bar 不与 system bars、cutout 或 IME 交叠
- `amethyst-glass` 的全屏伪元素是不可交互背景，允许延伸；legacy CSS 与用户自定义 CSS 不纳入本项保证

**重点观察**
- 主题按钮点击后是否“立刻变样式”
- 刷新页面后数据是否还在
- 删除订阅和移除主题是否只影响目标对象
- Console 里是否有新的业务错误
