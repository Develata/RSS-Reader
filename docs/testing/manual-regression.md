# 手工回归测试清单

这份清单用于共享 UI 的 Web、Windows 原生桌面与 Android 回归。各端分别记录结果：Windows Chrome 通过只代表 Web 路径，不能替代 Windows WebView2 或 Android 实机验收。
建议在这些场景下使用：

- 阅读页、订阅页、设置页有明显改动之后
- 主题系统或自定义 CSS 能力调整之后
- 发版前做一轮基础人工验收时

## 验收准备与 Windows 原生隔离

- 记录执行日期、完整 commit SHA、构建模式、产物路径与哈希、操作系统、浏览器或 WebView 版本、视口、显示缩放、主题和数据规模。每项填写“通过 / 失败 / 未运行”，并保留具体观察、截图或日志。
- Web 使用独立浏览器 profile。Windows 原生将本次构建的 exe 及所需资源复制到独立、可写的临时目录，避免使用日常安装目录和用户数据库。
- Windows 数据目录按 **exe 所在目录**决定，不按当前工作目录决定。测试数据库应位于 `<exe目录>/RSS-Reader/rss-reader.db` 与 `rss-reader-content.db`，界面偏好也位于该 `RSS-Reader` 目录。只改变 working directory 或 WebView2 profile 不能隔离 SQLite。
- 启动前，仅为本次子进程设置 `WEBVIEW2_USER_DATA_FOLDER` 到独立测试目录，核对实际使用的 profile 路径；避免全局修改环境变量或复用运行中的 profile。环境覆盖方式见 [Microsoft WebView2 环境创建说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/webview2-idl#createcorewebview2environmentwithoptions)。
- GUI 检查串行执行，保留用户已有窗口；只结束本次启动的实例。删除、导入与主题移除使用测试数据。重启持久化检查使用同一测试 exe 路径与 profile。
- 单次结果保存到 `target/**/summary.md`，交付摘要放 `docs/handoffs/`；本文件保留可复用清单和空白模板。

### 复用现有断言检查 Windows 原生窗口

在隔离的应用子进程中设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<空闲端口>`，从该实例的 `/json/list` 获取 `http://dioxus.index.html/` 对应的 target ID。测试库需已有多页文章、完整长来源名及带本地 data URI 图片和段落的正文；测试会正常打开文章并更新其已读状态。

```bash
node scripts/browser/rssr_small_viewport_assertions.mjs \
  --cdp-base http://127.0.0.1:9338 \
  --native-target TARGET_ID \
  --artifact-dir target/windows-native-smoke
```

该模式直接连接已有 Windows WebView2，复用 shell、截图、console 与几何断言，不创建浏览器标签页、不注入 localStorage、不模拟视口、不关闭宿主窗口。实际窗口尺寸、WebView 版本和点击至目标 DOM 更新后两帧的延迟写入 `assertions.json`。点击计时不包含 CDP 传输和点击前的定位滚动，不能当作完整输入延迟或屏幕光子响应时间。

断言覆盖搜索、导航、长来源、中段分页、阅读返回、图片查看、鼠标选择与 Ctrl+A。RSS 请求由原生 reqwest 发起，刷新去重需另用可计数的 loopback feed 验证；这些请求不能用浏览器 Fetch 拦截替代。系统剪贴板、安装包、Android 和 macOS 不在此模式的验收范围。

发现或连接失败会退出非零并写入失败报告；查看报告时同时核对本次进程退出码。运行结束由启动方关闭自己创建的应用，并核对 profile、数据库和临时进程归属。

## 共享交互清单（逐平台执行）

公开行为以[前端命令与界面接口清单](../design/frontend-command-reference.md)为准。现有自动化入口见[固定小视口 smoke](./static-web-small-viewport-smoke.md)和[Windows Chrome 可见窗口回归](./windows-chrome-visible-regression.md)。

### 1. Home、路由与搜索

- Web 打开 `/`；原生启动应用。确认进入全局文章页，顶部常态为 `[R] [搜索] [S] [设置]`，没有独立“文章”导航按钮。
- S 进入订阅、齿轮进入设置；从订阅、设置、单来源列表和 Reader 点击 R，只回到全局文章页，不因导航额外启动 RSS 刷新。
- 已在全局文章页时再次点击 R，启动一次刷新全部订阅；连续点击或与“刷新全部”重叠时不新增相同批次。用可计数的测试 feed 请求确认去重，区分既有自动刷新。
- 搜索图标展开输入框并收起 S / 设置；再次点击恢复 S / 设置。R 始终可见，Reader 左上角返回键也保留。
- 输入标题关键词按 Enter，进入全局文章页显示匹配结果；Esc 收起搜索，中文输入法组合输入期间不误收起。不新增字母 R 快捷键。
- icon-only 按钮有名称、title 和约 44×44 CSS px 触控区域。旧 `nav_hidden=true` 偏好不隐藏 R，不再检查已移除的顶部导航展开/折叠按钮。
- 页面切换正常，没有白屏或卡死；Web 浏览器重新加载当前路由仍可进入，不将浏览器 reload 当成 RSS 手动刷新。

### 2. 订阅管理

- 在“订阅”页添加一个有效 RSS URL
- 确认订阅列表出现该 feed
- 点一次 `刷新全部`
- 如果某个 feed 行有 `刷新此订阅`，也点一次
- 如果有 `删除订阅`，测试两步确认删除是否正常
- 手动刷新开始后立即进入 Reader，任务继续；完成或报错时不替换当前正文、不跳动滚动位置或清除选区，失败后能再次主动刷新。
- Reader 的刷新结果不盖住标题或正文；R 的状态标记、完整 title 和无障碍状态播报仍可用。

### 3. 文章列表与阅读

- 进入“文章”页
- 确认能看到文章列表
- 点开一篇文章进入阅读页
- 确认标题、来源、时间、正文都正常
- 返回文章页后列表仍正常
- Reader 返回图标位于最左上角，标题下方无旧大返回按钮。
- 来源筛选支持多选，完整来源名直接可读，不以 hover title、aria-label 或长按 tooltip 代替可见名称。
- 用长中文、含空格名称、无空格长串与极端标题验证换行；360px 视口不横向溢出，来源选择区可局部纵向滚动。
- 多页列表滚到中部，唯一一份紧凑分页仍可点击；首页/末页 disabled 状态明确，切页保持筛选、来源和分组，并回到新页起点。
- 月份、日期、来源目录仍能跳转整个结果集；分页不遮挡末尾内容，也不出现在 Reader。

### 4. 状态操作

- 点一次 `标记已读`
- 点一次 `收藏`
- 开关 `仅未读`
- 开关 `仅收藏`
- 输入标题关键词搜索
- 刷新页面后确认这些状态仍能正确显示

### 5. 主题切换

- 去“设置”页
- 用主题下拉选择一个预置主题，点 `应用所选主题`
- 确认页面样式立刻变化
- 用主题卡片点一次 `应用这套主题`
- 再点当前主题卡片的 `移除这套主题`
- 确认只移除了当前主题，不是异常清空别的内容
- 点 `导出当前 CSS`，确认能导出
- 如方便，再点 `导入主题文件` 导回一份 CSS

### 6. Android 主题导出（SAF，有设备时执行）

- 在 Android 设置页应用一套主题后点 `导出当前 CSS`
- 在系统保存器中取消，确认页面显示已取消且不报错
- 再次导出并保存，确认文件字节与当前 CSS 完全一致
- 保存器显示期间再次触发导出应被拒绝，不覆盖已有在途请求
- 使用拒绝写入或返回空输出流的测试 provider，确认页面报告错误且应用不崩溃
- 确认生成 manifest 不含存储权限；Android 主题文件导入仍是已知未实现项

### 7. 设置持久化

- 在“设置”页改一个普通设置，比如主题模式、刷新间隔或字号
- 点 `保存设置`
- Web 重新加载，原生关闭后从同一测试 exe 路径重启
- 确认设置仍保留
- 保存期间继续编辑的草稿不被旧保存结果覆盖。

### 8. 配置交换

- 到“订阅”页测试：
- `导出配置`
- `导出 OPML`
- 如方便，再做一次 `导入配置` 或 `导入 OPML`
- 确认没有报错，列表状态正常

### 9. Web 与原生持久化（分别记录）

- 关闭当前标签页
- 重新打开服务地址
- 确认订阅、设置、自定义 CSS 仍在
- 这一步是 Web 端最关键的本地持久化检查
- Windows 原生关闭后从同一测试 exe 重启，确认 SQLite 订阅、设置与自定义 CSS 保留；Web 成功不代替此项。

### 10. Android safe-area（API 35+ debug 预演，有设备时执行）

- 记录系统和 WebView 版本；debug edge-to-edge 预演与正式包分别记录，不能互相替代。
- 分别覆盖浅色/深色、竖屏/横屏、手势导航/三键导航，以及 IME 展开
- 确认 R、搜索输入、Reader 返回键、固定列表分页、当前主题侧栏和 Reader 底部栏不被 system bars、cutout 或 IME 遮挡
- `amethyst-glass` 的全屏伪元素是不可交互背景，允许延伸；legacy CSS 与用户自定义 CSS 不纳入本项保证

### 11. 原生文本选择与快捷键

- 默认主题下鼠标拖选正文、标题及合理的 metadata，确认原生选区正常。
- Windows 在正文选区按 Ctrl+C，粘贴到临时文本编辑器核对内容；Ctrl+A 保留原生全选行为，不触发已读、收藏或切篇。macOS 可用时独立验证 Cmd+C / Cmd+A。
- 搜索输入框中输入 m、f 与方向键，不改变文章状态或切篇。
- Android 可用时长按正文，确认原生选择手柄和复制操作；Reader 不响应下拉刷新，选择不被手势监听劫持。

### 12. 正文图片查看

- 滚到正文中间点击图片，确认查看器使用已渲染的地址；横图、竖图与大图可见，本地化图片或 data URI 不无故重新请求远端原图。
- 分别通过关闭按钮、背景与 Esc 关闭，确认正文滚动位置和焦点恢复；重复开关后背景仍可滚动，无残留浮层。
- 键盘聚焦正文图片后用 Enter / 空格打开；打开后焦点进入查看器，关闭按钮可操作。
- 图片打开时离开 Reader 再返回，正文仍可滚动。Android 系统返回应先关图片，再返回才离开 Reader；pinch 缩放单独记录实机结果。

### 13. Android 下拉刷新（有设备时执行）

- 仅全局文章页顶部向下拖动超过 80 CSS px 后松手触发，能看到 pulling / armed 和刷新结果反馈。
- 页面中部滚动、短距离拖动、横向或多指手势、表单操作、来源选择区内部滚动均不触发。
- 下拉与 R 共用进行中批次；Reader 正文选择和图片操作不触发下拉刷新。

### 14. 性能测量

- 固定修改前后的构建模式、主题、数据、窗口尺寸、网络条件与测量起止事件。Windows 至少检查真实 1280×800 窗口和窄窗口，记录显示缩放。
- 建议使用 800 / 2000 条文章 fixture，各做至少 5 次同条件样本，分别记录首次启动、同数据重启、切页和进入阅读耗时。记录内存采样时点，以及是否计入 WebView2 子进程。
- 保留原始样本与中位数，不把构建耗时、一次最快结果或浏览器 touch emulation 当作原生实机性能证据。

**重点观察**

- 主题按钮点击后是否“立刻变样式”
- 刷新页面后数据是否还在
- 删除订阅和移除主题是否只影响目标对象
- Console 里是否有新的业务错误
