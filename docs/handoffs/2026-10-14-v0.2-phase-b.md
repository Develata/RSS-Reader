## 工作摘要

阶段 B 按设计文档（`docs/design/v0.2-architecture.md`，架构与“阶段与门禁”）在界面与用例之间建立后端接缝，为阶段 C 的服务器端 Web（`HttpBackend`）铺路。门禁：先证明等价重构，再分别验收契约调整；正式 Web 依赖图不含 SQLite。

## 关键变更

### B1 第 0 步：界面接缝的特征测试

此前没有任何测试用真实用例驱动 `execute_ui_command`（盘点结论）。新增 `crates/rssr-app/src/ui/runtime/characterization.rs`：

- 内存资料库（`AppServices::over(store)`，由 `shared()` 拆出的非全局构造）+ 本地 HTTP 服务器（订阅源、发现页、失败的源、WebDAV 文件）；`UiServices::shared()` 在测试中经线程局部的 `test_host` 取得注入的实例。
- 按顺序执行 26 种 `UiCommand` 中的全部变体（含成功与失败分支；B1 复审后共 49 步），把产生的 `UiIntent`（Debug 文本）与记录的 `characterization.transcript` 比对；时间、本地时区偏移与端口规范化。`LoadAuthenticatedShell` 在无订阅的另一实例上执行（它会启动自动刷新循环）。
- 重新记录：`RSSR_UPDATE_UI_TRANSCRIPT=1 cargo test -p rssr-app --bin rssr-app characterization`，并审阅差异。
- 区分力：改一处状态文案、删除订阅时不清空文章，各自使测试失败（后者靠“删除后重新添加，文章重新变为未读”一步）。
- 稳定性：Windows 连续 3 次通过；WSL（EDT 与 `TZ=Asia/Shanghai`）通过。

### B1 第 1 步：`rssr-api` 与 `Backend` 接口

- 新 crate `crates/rssr-api`（只依赖 `rssr-application`、`rssr-domain`、`anyhow`、`async-trait`、`url`，不依赖 infra）。`Backend` 是平铺接口，26 个方法对应原 `UiServices` 五组端口的 27 个方法，类型不变（`anyhow::Result`、`usize` 等留给 B2）；`load_authenticated_shell` 与 `load_settings` 本就是同一个调用，合并为 `load_settings`。平铺而非分组：阶段 C 里一个方法对应一个 HTTP 端点，界面也不分别持有各组端口。
- 三个原先定义在 `rssr-app` 的结果类型（`AddSubscriptionOutcome`、`RefreshAllExecutionOutcome`、`RefreshFeedExecutionOutcome`）移入 `rssr-api`，`rssr-app` 改为引用。
- 验证：`rssr-api` 与 `rssr-app` 原生、wasm32 `clippy -D warnings` 通过；特征测试通过（转录未变）。

### B1 第 2 步：界面改走 `Arc<dyn Backend>`

- `ui/runtime/services.rs`（`UiServices` 与五组端口）换成 `ui/runtime/backend.rs`：`backend()` 返回 `Arc<dyn Backend>`，`LocalBackend` 以原端口方法的同样实现满足接口；运行层各命令改为调用接口方法（端口取值器去掉，方法按接口改名）。构造开销与原来相同（每条命令取一次共享服务），缓存留给第 3 步。
- 宿主能力接口加了 `HostBound` 约束：原生平台要求 `Send + Sync`（`Backend` 的 future 在原生是 `Send`），wasm32 不要求。wasm32 上 `Arc` 包非 `Send` 的后端，按单线程放行 `arc_with_non_send_sync`。
- 验证：特征测试通过、转录未变；`rssr-app` 121 + 2 + 2 passed；`rssr-app` / `rssr-api` 原生与 wasm32 `clippy -D warnings` 通过；Android `cargo check` 通过。

### B1 第 3 步：共享的 `LocalBackend` 移入 infra

- 新模块 `rssr_infra::local_backend`：`LocalBackend<H>` 实现 `Backend`，所有在本机运行用例的宿主共用——添加订阅（准备、保存并刷新）、刷新全部（`RefreshFlight` 合并重叠批次，从 `rssr-app` 移来）、刷新结果转成界面结果、自动刷新循环（时间规则与 6 个测试从 `rssr-app` 移来）。
- 平台差异收进 `LocalHost`：后台任务、睡眠、时钟、远端配置存储、刷新后与按需的图片本地化、刷新并发度、能否联网、是否运行自动刷新。原生 `NativeHost` 与 `native_local_backend(store)`（按 journal 模式定并发度）在 infra，连同图片本地化 worker 及其 3 个测试；Web 的 `WebHost` 留在 `rssr-app/src/bootstrap/web.rs`（演示站开关、gloo 计时器在那里）。阶段 C 的服务器会用同一个 `NativeHost`。
- `rssr-app`：`HostCapabilities`、四个能力接口、两份重复的刷新编排、`web/refresh.rs`、`web/exchange.rs` 删除；`AppServices` 只持有 `Arc<LocalBackend<…>>`，`backend()` 克隆这个 `Arc`——每条命令不再克隆 13 个服务、新建 4 个 `Arc`。
- 行为差异（仅日志）：原生自动刷新失败的日志字段由 `?error` 改为与 Web 相同的 `%error`。
- 验证：特征测试转录未变；`rssr-app` 110 passed（另 11 个测试随代码移入 infra，`local_backend` 下 11 passed）；工作区 52 个套件 504 passed；`rssr-app` / `rssr-api` / `rssr-infra` 原生与 wasm32（含 `pages-demo`）`clippy -D warnings` 通过；Android `cargo check` 通过。

### B1 第 4 步：依赖图门禁写成测试

### B2-D1：原子端口成为必需依赖（`89ec076`）

- `ImportExportService::new(feeds, …, config_replacement)` 只有一个构造函数，配置替换只走 `ConfigReplacementPort`（一次存储事务）；分步替换的回退路径及只有它使用的清理端口删除。
- `FeedRepository::upsert_subscriptions` 不再有逐条的默认实现：两种存储各自一次事务实现，测试替身显式写出。
- 测试：application 测试核对交给端口的计划、无效配置包不会到达端口；契约与配置包测试只跑原子路径。
- 验证（提交时）：工作区 53 个测试套件 501 passed / 0 failed / 3 ignored；clippy 原生与 wasm 通过；wasm harness 4 / 26 / 30 通过。遗漏：`wasm_config_exchange_contract_harness` 留下两个不再使用的导入（`cargo check --tests --target wasm32` 才报），D2 中删除。

### B2-D2：聚合读快照

- 新端口 `rssr_application::LibraryQueryPort`（`library_queries.rs`）：`entries_page`（一页文章 + 可选计数）、`reader_snapshot`（记录、正文、导航、所属的有效订阅）、`entries_start`（设置、列表偏好、订阅摘要，按需）、`startup_state`（设置 + 仍有效的“上次打开”）、`config_snapshot`（有效订阅 + 设置）。
- 实现：原生 `store::LibraryQueries`，每个方法一次 `store.read`（一个读事务）；浏览器 `BrowserLibraryQueries`，每个方法一次 `BrowserStore::read`（Web Lock 下读同一份已提交状态）。两者复用各自已有的查询函数，不新增 SQL。
- 用例改走端口：`EntriesListService::list_entries`（归档计数的查询由 application 构造）、`ReaderService::load_entry`（订阅名称：有文字的自定义名称，否则地址）、`EntriesWorkspaceService::bootstrap`（读取时写“上次打开”的旧行为保留到 D6）、`StartupService`（只依赖端口）、`ImportExportService::export_config`（不再持有设置仓储）。`AppCompositionInput` 增加 `library_queries`，删除只剩阅读页使用的 `entry_content_repository`。
- 行为变化只在错误路径：快照整体成功或整体失败。阅读页不再在导航或订阅读取失败时照常显示正文；启动时读不到应用状态会显示错误（界面照旧回到全部文章），原先静默回退。订阅页仍是一条查询，D4 加指纹时并入端口。
- 测试：application 单元测试经 `#[cfg(test)]` 的 `RepositoryQueries`（逐个仓储读取，只供测试）驱动；新增归档计数查询的核对、“快照部分失败即整体失败”；删除两条分步容错的旧测试。新增 `test_library_queries`（5 个，原生端各查询的返回内容）与浏览器 harness 用例 `library_queries_leave_out_removed_subscriptions`。快照的一致性本身由存储读事务保证（`test_library_store::a_read_task_sees_one_snapshot`）。
