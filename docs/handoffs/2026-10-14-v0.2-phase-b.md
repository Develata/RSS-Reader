## 工作摘要

阶段 B 按设计文档（`docs/design/v0.2-architecture.md`，架构与“阶段与门禁”）在界面与用例之间建立后端接缝，为阶段 C 的服务器端 Web（`HttpBackend`）铺路。门禁：先证明等价重构，再分别验收契约调整；正式 Web 依赖图不含 SQLite。

分两半：

- **B1 等价重构**（行为不变）：特征测试 → `rssr-api` 的 `Backend` 接口（沿用现有类型）→ 界面改走 `Arc<dyn Backend>` → 原生与 Web 重复的宿主编排移入 infra 的共享 composition → 依赖图门禁写成测试。
- **B2 契约调整**（公开契约变化）：设备状态移出资料库、错误契约、切换语义、设置的修改输入、公开类型（固定宽度计数、RFC3339、去掉内部数据）。逐项写成决策清单，经独立设计评审和 Develata 确认后实施。

阶段 A 的遗留项（macOS / Android 实机、磁盘不足、真实 checkpoint）留在 `2026-10-13-v0.2-architecture.md`，不并入本阶段。

## 关键变更

### B1 第 0 步：界面接缝的特征测试

此前没有任何测试用真实用例驱动 `execute_ui_command`（盘点结论）。新增 `crates/rssr-app/src/ui/runtime/characterization.rs`：

- 内存资料库（`AppServices::over(store)`，由 `shared()` 拆出的非全局构造）+ 本地 HTTP 服务器（订阅源、发现页、失败的源、WebDAV 文件）；`UiServices::shared()` 在测试中经线程局部的 `test_host` 取得注入的实例。
- 按顺序执行 26 种 `UiCommand` 中的全部变体（含成功与失败分支，共 40 步），把产生的 `UiIntent`（Debug 文本）与记录的 `characterization.transcript` 比对；时间、本地时区偏移与端口规范化。`LoadAuthenticatedShell` 在无订阅的另一实例上执行（它会启动自动刷新循环）。
- 重新记录：`RSSR_UPDATE_UI_TRANSCRIPT=1 cargo test -p rssr-app --bin rssr-app characterization`，并审阅差异。
- 区分力：改一处状态文案、删除订阅时不清空文章，各自使测试失败（后者靠“删除后重新添加，文章重新变为未读”一步）。
- 稳定性：Windows 连续 3 次通过；WSL（EDT 与 `TZ=Asia/Shanghai`）通过。

### B1 第 1 步：`rssr-api` 与 `Backend` 接口

- 新 crate `crates/rssr-api`（只依赖 `rssr-application`、`rssr-domain`、`anyhow`、`async-trait`、`url`，不依赖 infra）。`Backend` 是平铺接口，27 个方法与原 `UiServices` 五组端口的方法一一对应，类型不变（`anyhow::Result`、`usize` 等留给 B2）；`load_authenticated_shell` 与 `load_settings` 本就是同一个调用，合并为 `load_settings`。平铺而非分组：阶段 C 里一个方法对应一个 HTTP 端点，界面也不分别持有各组端口。
- 三个原先定义在 `rssr-app` 的结果类型（`AddSubscriptionOutcome`、`RefreshAllExecutionOutcome`、`RefreshFeedExecutionOutcome`）移入 `rssr-api`，`rssr-app` 改为引用。
- 验证：`rssr-api` 与 `rssr-app` 原生、wasm32 `clippy -D warnings` 通过；特征测试通过（转录未变）。

### B1 第 2 步：界面改走 `Arc<dyn Backend>`

- `ui/runtime/services.rs`（`UiServices` 与五组端口）换成 `ui/runtime/backend.rs`：`backend()` 返回 `Arc<dyn Backend>`，`LocalBackend` 以原端口方法的同样实现满足接口；运行层各命令改为调用接口方法（端口取值器去掉，方法按接口改名）。构造开销与原来相同（每条命令取一次共享服务），缓存留给第 3 步。
- 宿主能力接口加了 `HostBound` 约束：原生平台要求 `Send + Sync`（`Backend` 的 future 在原生是 `Send`），wasm32 不要求。wasm32 上 `Arc` 包非 `Send` 的后端，按单线程放行 `arc_with_non_send_sync`。
- 验证：特征测试通过、转录未变；`rssr-app` 121 + 2 + 2 passed；`rssr-app` / `rssr-api` 原生与 wasm32 `clippy -D warnings` 通过；Android `cargo check` 通过。
