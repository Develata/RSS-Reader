### B1 第 2 步：界面改走 `Arc<dyn Backend>`

- `ui/runtime/services.rs`（`UiServices` 与五组端口）换成 `ui/runtime/backend.rs`：`backend()` 返回 `Arc<dyn Backend>`，`LocalBackend` 以原端口方法的同样实现满足接口；运行层各命令改为调用接口方法（端口取值器去掉，方法按接口改名）。构造开销与原来相同（每条命令取一次共享服务），缓存留给第 3 步。

### B2-D5a：错误码与可识别的错误类别

- 领域：`DomainError` 增加 `Network`、`Unavailable`。存储错误转换保留可处理的类别：约束冲突 → `Conflict`，忙 / 中断 / 等待连接超时 → `Unavailable`，其余 → `Persistence`。`remove_subscription` 与 D4a 的 `update_settings` 改为先转成 `DomainError` 再进入错误链（此前 `StoreError::Domain` 是 transparent，链上认不出里面的领域错误）。
- application：`error.rs` 的 `ErrorKind` 与 `classify`：取错误链中第一个 `DomainError` 定类别，上下文不影响；没有就是 `Internal`。只有输入无效、未找到、冲突、网络四类显示自身说明，其余显示固定说明并在这里记录完整错误链。面向用户的输入错误显式标为 `InvalidInput`：重复订阅、订阅 URL、订阅发现失败、配置包 JSON、OPML。刷新不存在的订阅 → `NotFound`。
- infra：远端失败统一经 `remote_failure::{invalid, network}`。订阅探测时，地址协议不对 → `InvalidInput`；取回过程 → `Network`；响应既不是 feed 也不是网页 → `InvalidInput`。WebDAV（原生与浏览器）的远端路径与 endpoint → `InvalidInput`，传输与状态码 → `Network`。Pages 演示的网络开关 → `Network`。
- `rssr-api`：`BackendError { code: ErrorCode, message, request_id }`（`Display` 即说明；`ErrorCode::as_str` 为线上字符串），由 `From<anyhow::Error>` 经 `classify` 构造；`Backend` 的所有操作返回它。`RefreshFlight` 共享分好类的错误，不再共享文本；等待方因发起方被取消而落空时为 `Unavailable`。界面的 `backend()` 同样返回 `BackendError`，导入冲突改按 `code` 判断（删除 D4b 的错误链遍历）。设置页 WebDAV 拉取遇到冲突时，现在会显示冲突原因，不再被上下文“替换配置失败”盖住。
- 特征测试转录：四条错误文字变化。设置的两条去掉“输入无效：”前缀；JSON 与 OPML 两条加上“配置包不是有效的 JSON：”“OPML 无法解析：”。其余步骤不变。界面不显示错误码，错误码由单元测试覆盖。
- 测试：`classify` 各类别、上下文不改变类别；`BackendError` 的 code 与字符串；存储错误映射；`LocalBackend` 逐个错误码：设置补丁无效、删除 / 刷新不存在的订阅、非法 URL、损坏的 OPML、过期指纹、损坏的 JSON。`unavailable` 需要被占用的资料库、`network` 需要远端，分别由存储映射测试与远端适配器的类型标注保证，未做端到端用例。
- CLI 不经 `Backend`，继续打印完整错误链。

### B2 复核（Codex gpt-6-astra，max，`c7cccac..1fe50ba`）与修复（`ded0142`）

结论 FAIL（1 个阻断项、2 个应修、2 个待核实）。原第 1、3、4、5 项确认已修复。逐条核实与处理如下。第 1–3 项的原生测试（设置页三个反例、`archive_boundary_cases` 的原生运行、导入的小写 `t`）先在修复前的代码上运行并失败，修复后通过；浏览器端的整秒用例与第 5 项的分类断言没有先在修复前运行（分类断言检验的是已有行为，生产代码未改）：
