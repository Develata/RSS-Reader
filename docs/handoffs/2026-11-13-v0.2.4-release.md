## 工作摘要

本版发出 WebDAV 自动同步与用户名 / 密码分栏（PR #74）、macOS 系统菜单与编辑快捷键（PR #72）、文章列表与计数的查询改写及迁移 0003（PR #73）。发版前在 main `c774f161` 上核对：三个 PR 均已合并，main 的 CI、Pages、Docker 全绿，没有未合并的 PR，workspace 版本 0.2.3 与最新发布一致。Develata 在知道 WebDAV 仍有未决事项（无强 ETag 时是否停用自动上传、坚果云 / Nextcloud 与界面手工验收未做）的情况下决定照常发布。

## 关键变更

### 发布流程

- 版本号按惯例取补丁版：v0.2.1 带迁移 0002 时同样只升补丁号。`cargo update --workspace` 只改动 `Cargo.lock` 中 7 个成员的版本；`cargo metadata --locked` 显示全部为 0.2.4，本地 `rssr-cli --version` 输出 `rssr 0.2.4`。
- PR #75 的 16 项检查通过、`deploy` 按设计跳过，用 `--match-head-commit a9b03926` 合并。合并提交 `87ce46c6` 与 PR head 的树完全相同（PR 基于当时的 main `c774f161`），因此没有等 main 的 push CI 跑完就打了 tag。
- Annotated tag `v0.2.4` 用本机 git 身份创建；回读远端 `refs/tags/v0.2.4^{}` 为 `87ce46c6`。
- [Release 工作流 43435183149](https://github.com/Develata/RSS-Reader/actions/runs/43435183149) 第一次 attempt 即全部成功（`build-container / build-package` 按设计跳过），用时约 20 分钟。前三版在 macOS runner 上安装 Dioxus CLI 时超时的问题这次没有出现。其中 `build-linux` 的“安装包并以普通用户启动”与 `build-container / image` 的“新卷、旧库迁移与所有者 CLI”两步通过。
- Release 于 2026-11-13T13:56:48Z 发布，非 draft、非 prerelease，共 14 个附件。工作流发布时正文为空；随后用 `gh release edit --notes-file` 写入[发布说明](../releases/v0.2.4.md)正文，相对链接改为指向 main 上文档的绝对地址。

### 文档

- `docs/deployment/web.md` 原写“`latest` 会随主线镜像构建或后续发布变化”，与工作流不符：`docker.yml` 只在 `use_existing_package` 且给出 `image_tag` 时推送（即由 `release.yml` 调用时），main 上的 push 只在 runner 上构建并验收镜像。已改为 `latest` 只随正式发布更新。

## 验证与验收

### 已核对

- 附件哈希：macOS 两种架构的应用与 CLI、`RSS-Reader-linux-x86_64.deb`、`rssr-cli-linux-x86_64.tar.gz` 共 6 个附件，`shasum -a 256 -c` 与 GitHub API 的 `digest` 一致。
- macOS 应用包（两种架构）：
  - 归档里没有 AppleDouble 条目。
  - `codesign --verify --deep --strict` 通过；`Signature=adhoc`，`Sealed Resources version=2`，Identifier 为 `io.github.develata.rssreader`。
  - `CFBundleName`、`CFBundleDisplayName` 为 `RSS-Reader`，`CFBundleShortVersionString`、`CFBundleVersion` 为 `0.2.4`。
- macOS CLI 分别为 arm64 / x86_64 Mach-O；arm64 版输出 `rssr 0.2.4`。deb 控制信息 `Version: 0.2.4`、`Architecture: amd64`。
- 用隔离的 HOME 直接启动 aarch64 应用的可执行文件：10 秒后进程仍在，日志显示资料库已打开、WAL 已启用、自动刷新已触发；`library.sqlite3` 建在临时 HOME 的 `Library/Application Support/RSS-Reader/` 下，`schema_migrations` 为 1、2、3，`integrity_check` 为 `ok`。核对后结束进程。
- 升级与回退（v0.2.3 与 v0.2.4 的 aarch64 CLI，`--data-dir` 指向临时目录，`show-settings`）：v0.2.3 新建的库迁移为 1、2；v0.2.4 打开后为 1、2、3，`integrity_check` 为 `ok`；随后 v0.2.3 以退出码 1 拒绝打开，报“资料库由更新版本的程序创建（结构版本 3）”。与发布说明一致。
- `cargo binstall --git https://github.com/Develata/RSS-Reader rssr-cli --disable-strategies compile` 安装到 scratch root，装上的版本输出 `rssr 0.2.4`。
- GHCR 匿名查询：`v0.2.4` 与 `latest` 的摘要都是 `sha256:44f2b35b4e464b77c03e42580432319c09e0f6bc940f07a9b78483157cd9ee65`。

## 结果

- v0.2.4 已公开发布。`cargo binstall --git` 现在装到 v0.2.4；main 的 workspace 版本为 0.2.4。
- 升级后的资料库不能再由 v0.2.3 及更早版本打开，回退需恢复升级前备份；发布说明、README 与部署说明均已写明。
- 本机 `/Applications/RSS-Reader.app` 已由 0.2.3 换成核对过的 aarch64 附件（旧版移到废纸篓 `RSS-Reader-0.2.3.app`）。升级前用 `sqlite3 .backup` 备份资料库到 `~/Library/Application Support/RSS-Reader-backup-2026-11-13-v0.2.3.sqlite3`（迁移 1、2，完整性 `ok`，10 个订阅、1629 篇文章）；新版启动后迁移到 1、2、3，`quick_check` 为 `ok`，订阅与文章数不变。正式包的菜单栏没有核对：读取它需要给终端辅助功能授权，没有改系统设置。

## 风险与后续事项

- WebDAV：服务器不给强 ETag 或不执行 `If-Match`（OpenList 即如此）时可能覆盖另一台设备的上传。发布后 Develata 采纳建议，不因此停用自动上传；理由与源码核对见[设计](../design/webdav-auto-sync.md)“已知限制”。本版发布后，`rss-reader.json` 固定文件名、用户名 / 密码分栏与 `remote-sync.json` 已是公开行为，再改要考虑已有用户的迁移。
- 迁移 0003 的打开期限风险见[存储交接](./2026-11-12-storage-linear-queries.md)“风险与后续事项”。
- macOS 菜单没有自动化回归测试（见[快捷键交接](./2026-11-12-macos-edit-shortcuts.md)）。
