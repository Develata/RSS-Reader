## 验证与验收

### 已核对

- macOS 四个附件（`RSS-Reader-macos-{aarch64,x86_64}.tar.gz`、`rssr-cli-macos-{aarch64,x86_64}.tar.gz`）：`shasum -a 256` 与 GitHub API 的 `digest` 一致。两个应用归档里都没有 `._` AppleDouble 条目。
- 两个 `RSS-Reader.app`：
  - `codesign --verify --deep --strict` 报 `valid on disk`、`satisfies its Designated Requirement`。
  - `Signature=adhoc`，`Sealed Resources version=2`，Identifier 为 `io.github.develata.rssreader`。
  - `CFBundleName` 与 `CFBundleDisplayName` 都是 `RSS-Reader`，`CFBundleShortVersionString` 与 `CFBundleVersion` 都是 `0.2.3`。
- CLI 分别为 arm64 / x86_64 Mach-O；arm64 版本机运行 `--version` 输出 `rssr 0.2.3`。
- `syspolicy_check distribution`（aarch64 包）：v0.2.2 的 “code has no resources” 错误消失，剩下的只有 adhoc 警告和 “Notary Ticket Missing”，后者是没有公证时的预期结果。不带隔离标记时 `spctl -a -t exec` 为 rejected，同样是因为没有 Developer ID。
- 用隔离的 HOME 直接启动 aarch64 应用的可执行文件：进程常驻，日志显示资料库已打开、WAL 已启用、自动刷新已触发，`library.sqlite3` 建在临时 HOME 的 `Library/Application Support/RSS-Reader/` 下。核对后结束进程。
- `cargo binstall --git https://github.com/Develata/RSS-Reader rssr-cli --disable-strategies compile`，安装到 scratch root：装上的版本输出 `rssr 0.2.3`。
- GHCR 匿名查询：`v0.2.3` 与 `latest` 的摘要都是 `sha256:98205ed7c526299425be8a8daab0c608c984e634d9ae6e72d4464eead399b581`（核对时；`latest` 之后会随主线变化）。
