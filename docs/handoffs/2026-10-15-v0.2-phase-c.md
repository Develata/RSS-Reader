### C1 出站访问策略

- 地址判定（`outbound/address.rs`）：全局可路由单播地址的允许清单，依据 IANA 特殊用途登记，另有几处有意更严。
  - 众所周知的 NAT64 前缀按内嵌 IPv4 判定，使 IPv6-only 服务器借 DNS64 仍能访问 IPv4-only 站点；其他内嵌 IPv4 的形式一律拒绝。
  - 用一个未提交的临时测试实测：旧判定接受 `192.0.0.1`、`::ffff:192.0.0.1`、`64:ff9b::a00:1`、`64:ff9b:1::a00:1`、`2002:a00:1::1`、`2001::1`，新判定全部拒绝。
- 策略（`outbound.rs`）：`Unrestricted` 或 `PublicOnly { allow, deny }`（`deny` 优先）。每一跳都在三处检查，互不替代：
  1. 发出前检查协议与字面地址；
  2. 解析器只返回放行的地址，任一应答被拒绝则整体失败；
  3. 重定向钩子再检查每一跳。
  `PublicOnly` 的客户端不用代理。
- 四条请求路径都有带策略的构造方法，客户端构建失败即报错，不退回默认客户端。各路径原有的重定向、认证、降级与 Referer 规则保持不变。
- 策略文件（`outbound/policy_file.rs`）：
  - 只有确实不存在才是 `Unrestricted`；符号链接、FIFO、非普通文件、格式错误，以及（Unix）属主不对或可被他人写入的文件都报错。
  - 以不跟随链接、不阻塞的方式打开，检查与读取用同一个描述符。
  - 服务器的默认策略先写临时文件并同步，再以硬链接发布，不覆盖已有文件。
- CLI 在打开资料库之前读取数据目录的策略，所有出站请求（含 WebDAV）按它执行。

### C1 代码评审（Codex gpt-6-astra，max，`07f0c21..5fff0d0`）与修复

结论 FAIL（1 个阻断、6 个应修、1 个待核实、1 个可选）。逐条核实，都属实：

1. 阻断：Windows 上先用 `symlink_metadata` 检查、再用会跟随链接的普通打开读取。两步之间若换成悬空链接，打开返回“不存在”，CLI 就按 `Unrestricted` 运行。
   - 修复：Windows 只打开一次，带 `FILE_FLAG_OPEN_REPARSE_POINT`，句柄就是链接本身，类型检查不通过。
   - Windows 上建符号链接需要开发者模式，没有加竞态测试。
2. 拒绝错误保留完整 URL（含用户信息与查询中的令牌）：现在只写协议、主机与端口，有单元测试。
3. 服务器默认策略发布在目录属主检查之前：改为先检查数据目录属主，错误的用户启动不会留下文件。
4. 混合 DNS 应答没有在真实请求路径上测试；WebDAV 只测了 GET；图片只拒绝了后台本地化；特殊字面地址没有对照。全部补齐，见下。
5. 计数为零可能早于监听方取走连接：改为读数前先建立一个哨兵连接，等它被取走（`accept` 按队列顺序），之前到达的连接都已计入。
6. 绑定 `127.0.0.2/.3` 在默认的 macOS 上失败：全部改用 `127.0.0.1`。允许与拒绝的目标靠主机名区分：策略的解析器读取测试用的固定应答（`PublicOnly::with_fixed_answers`，文档隐藏，生产不用）。
7. 默认策略的临时文件可能删掉别人的：名字被占用时换名，只删本次创建的那个。
8. 待核实：作者运行的结果无法由评审独立确认。命令与输出见下，原始日志在本机暂存目录。
9. 可选：普通 CLI 在客户端构建失败时不再退回默认客户端。已恢复：`Unrestricted` 一律走原来的构造（`compose_library_use_cases_with` 与 `native_local_backend_with` 直接委托）。

重写后的集成测试 `test_outbound_policy`：
- 每条路径（feed、订阅探测、后台与阅读页图片、WebDAV 下载与上传）都试五种拒绝情形：字面地址、从放行主机重定向、被拒绝的主机名、混合应答（两种顺序）；
- 每条路径都在同一个客户端上做放行对照；
- 字面地址的各种写法另有不受限客户端的对照，证明每种写法都能连到监听方。

变异检验（feed 路径，在已提交的代码上进行）：去掉发出前检查、去掉重定向检查、把“全部应答都放行”改成“任一放行”，各自使测试失败。
