### C1 出站访问策略

- 地址判定（`outbound/address.rs`）：全局可路由单播地址的允许清单，依据 IANA 特殊用途登记，另有几处有意更严。
  - 众所周知的 NAT64 前缀按内嵌 IPv4 判定，使 IPv6-only 服务器借 DNS64 仍能访问 IPv4-only 站点；其他内嵌 IPv4 的形式一律拒绝。
  - 用一个未提交的临时测试实测：旧判定接受 `192.0.0.1`、`::ffff:192.0.0.1`、`64:ff9b::a00:1`、`64:ff9b:1::a00:1`、`2002:a00:1::1`、`2001::1`，新判定全部拒绝。
- 策略（`outbound.rs`）：`Unrestricted` 或 `PublicOnly { allow, deny }`（`deny` 优先）。每一跳都在三处检查，互不替代：
  1. 发出前检查协议与字面地址；
  2. 解析器只返回放行的地址，任一应答被拒绝则整体失败；
  3. 重定向钩子再检查每一跳。
  `PublicOnly` 的客户端不用代理。
- 四条请求路径都有带策略的构造方法，客户端构建失败即报错，不退回默认客户端。各路径原有的重定向、认证、降级与 Referer 规则保持不变。
- 策略文件（`outbound/policy_file.rs`）：
  - 只有确实不存在才是 `Unrestricted`；符号链接、FIFO、非普通文件、格式错误，以及（Unix）属主不对或可被他人写入的文件都报错。
  - 以不跟随链接、不阻塞的方式打开，检查与读取用同一个描述符。
  - 服务器的默认策略先写临时文件并同步，再以硬链接发布，不覆盖已有文件。
- CLI 在打开资料库之前读取数据目录的策略，所有出站请求（含 WebDAV）按它执行。

### C2 认证（`706d250` 与接线提交）

- 认证库（`crates/rssr-web/src/auth/store.rs`）：数据目录里的 `auth.sqlite3`，rusqlite（与资料库同一份捆绑 SQLite），一个连接，操作在阻塞线程上运行。
  - `owner`：Argon2 哈希、凭据代数、设备标记密钥。`sessions`：令牌摘要、创建时间、最后记录的使用时间、凭据代数。
  - 会话令牌 32 字节随机，库里只存带用途标签的 SHA-256 摘要。
  - 规则（`Stored::verdict`，时间由调用方传入）：
    - 拒绝条件依次检查：时钟回拨超过 5 分钟、凭据代数不一致、满 180 天、空闲满 30 天加 1 小时；
    - 拒绝即删除；删除失败时记为本进程的待吊销，一直拒绝并重试（第一轮评审 B1）；
    - 续期每小时最多写一次，用 `UPDATE … WHERE last_used_at <= now - 3600`：只更新仍存在的行，且从不往回改；需要续期却写不进时拒绝这次请求（第一轮评审 S1）；
    - 服务器启动时清理失效会话。运行标记在启动时落盘，正常停止且待吊销全部删掉之后才移除；启动时发现它就吊销全部会话（第二轮评审 B-1）。
    - 结束运行时在锁内关闭认证库，之后的会话操作一律报错；停止各段有总时限；同一数据目录只能有一个服务器（第三轮评审 R3-B1、R3-S1、R3-S2）。
  - 登录：同一次读取拿到哈希与凭据代数，在阻塞线程上核对密码（沿用原有的名额与限速）。建立会话的语句再核对代数，并顺带清掉已经过期的会话。
  - 改密码：一个事务里换哈希、凭据代数加一、删除全部会话。`revoke_all` 只删会话。
  - 文件以 0600 新建。Unix 上数据目录与认证库必须属于运行用户：目录不能被他人写，认证库不能被他人读。打开时不跟随符号链接。
- 凭据迁移（`credentials.rs`、`legacy_state.rs`）：认证库没有凭据时，按 `RSS_READER_WEB_PASSWORD_HASH`、`RSS_READER_WEB_PASSWORD`、旧认证状态文件的顺序取第一个可用的。旧文件只读，不改权限。建立之后这些变量被忽略，并记一条警告。
- 请求校验（`origin.rs`、`auth.rs`）：
  - 所有非 GET / HEAD / OPTIONS 请求的 `Origin` 必须与信任来源逐字一致，缺少或为 `null` 时拒绝。
  - 信任来源：设置了 `RSS_READER_WEB_PUBLIC_ORIGIN` 就只信任它；否则只允许监听回环地址，信任来源取自实际绑定的套接字（端口为 0 时也正确）。
  - 生产环境要求公开来源是 https；cookie 的 `Secure` 跟随公开来源的协议。
  - `/api` 下：未登录返回 JSON 401，不存在的接口返回 JSON 404，从不落入页面回退；写请求还要带 `X-RSSR-CSRF`。`GET /api/v1/session` 返回 `csrf_token`，带 `no-store`，不带任何跨源头。
  - `GET /logout` 是确认页，表单带 CSRF 令牌；`POST /logout` 核对 Origin 与令牌（表单字段或请求头）后吊销会话、清 cookie。
  - 认证库出错时拒绝请求（503 / JSON 503），偏于关闭。同时校验的会话最多 64 个，满了直接 503，不排队（第一轮评审 V1）。
- 子命令：`rssr-web passwd`（从标准输入读一行）与 `rssr-web sessions revoke-all`。数据目录用 `--data-dir` / `RSSR_DATA_DIR` 指定，必填。
- 删除冒烟辅助路由 `/__codex/*`（`smoke.rs`）。冒烟页与 feed 夹具改为静态文件（`scripts/browser/rssr_web_feed_smoke.html`），由 `scripts/prepare_rssr_web_feed_smoke.sh` 放进复制出的 bundle。冒烟经真实登录表单进入（`cdp_session.mjs` 的 `submitLoginForm`）。
- 同一提交改写的脚本与 CI：

### C5 备份与恢复（`rssr-cli backup`，计划第 4 步）

- `store::backup::backup_library(资料库文件, 目标, 选项, 取消)`（`backup.rs`）在一个专属线程上、用自己的连接完成全部步骤，线程从头到尾持有锁与临时文件，SQLite 停下之后才释放、删除：
  1. 只打开已存在且确认是资料库的文件（`files::check_library`；连接不带 `SQLITE_OPEN_CREATE`），不建库、不导入 v0.1 旧库；连接用 `connection::configure`（可写角色：`VACUUM INTO` 在 `query_only` 连接上报“只读数据库”，已用 SQLite 实测）。
  2. `<目标>.lock` 上的咨询锁（标准库 `File::try_lock`，有限等待，可取消）。锁文件必须是普通文件：先查 `symlink_metadata`，打开时不跟随链接（Unix 上 `O_NONBLOCK | O_NOFOLLOW`，FIFO 不会卡住打开；Windows 上 `FILE_FLAG_OPEN_REPARSE_POINT`），再用句柄的元数据确认。锁文件只锁、从不写入。
  3. 临时文件放在目录 `<目标>.partial` 里：不存在时以 0700（Unix）创建，只建这一层；已存在时必须是目录，`symlink_metadata` 看到的普通文件或链接（含 Windows 的目录联接）一律拒绝。持锁后先删除这个目录里名为 `partial-<32 位小写十六进制>`（可带 `-journal`、`-wal`、`-shm`）的条目——只可能是本目标死掉的备份留下的，包括发布之后被杀的——其他条目不动，再判定目标是否已存在。
  4. “仅在不存在时创建”临时文件 `<目标>.partial/partial-<32 位十六进制>`（随机名是标准库散列器在随机密钥下的两个输出，见 `nonce` 的注释；Unix 上 0600），`VACUUM INTO`（进度处理器每 1000 条指令检查取消与时限），关闭连接，检查取消，以可写句柄同步并取得大小（Windows 的 `FlushFileBuffers` 要求可写句柄），确认是资料库。
  5. 发布前最后一次检查取消；之后以硬链接发布（已存在时原子失败；不支持硬链接时报错，不退回改名）。发布之后没有会失败的步骤：删除临时名及其附属文件、目录为空时删除目录（不递归）、同步目标所在目录（Windows 没有目录句柄可同步，跳过）的失败只记日志，报告的大小取自发布前。
- 在目标所在目录里，协议从不改动它在这次运行之前就存在的文件的内容：只“仅在不存在时”创建文件和目录、建硬链接、删除名字，从不写入或截断已有的文件（第四轮 R4-01、R4-02）。资料库本身经 SQLite 读取，连接关闭时 SQLite 可能做 WAL 检查点，这不在此列（见“时限与限制”）。
- 前提（Develata 2026-10-19，第五轮评审之后决定）：目标所在目录只由运行备份的用户掌控，其中没有刻意制造的别名——没有硬链接、符号链接或挂载（含 bind mount）让备份的锁文件或临时目录成为别的文件、别的目录的另一个名字。前提之内，协议用到的每个名字都是它看上去的那个普通名字；同一目标的两种写法被文件系统当作同一个名字时（不区分大小写的文件系统），`<目标>.lock` 与 `<目标>.partial` 也被当作同一个名字：同一个目录、同一个主干、同一个 ASCII 后缀，折叠大小写与规范化不改变这个后缀。所以持有的锁与清理的目录属于同一个目标（R2-02、R3-02）。协议另外拒绝能查到的几种别名（锁文件不是普通文件，Unix 上锁文件有别的名字，临时目录的名字不是目录或是链接），这是保险而不是防御：查不出 bind mount，也不防备运行中被替换的名字。前提之外的情形记为已知限制，不作为评审的阻断项。
- 锁文件的检查（第五轮 R5-02）：Unix 上锁文件若有别的名字（硬链接数大于 1），打开之前就拒绝——同一进程里关闭某个数据库文件的第二个描述符，会释放 SQLite 在它上面持有的 POSIX 锁。清理临时目录时逐项检查取消，逐项读取的耗时与目录里的条目数成正比（R5-03）。临时目录删除失败时，除“目录非空”与“已不存在”之外都记日志（R5-06）。
- 目标名必须以 `.sqlite3`（精确的 ASCII）结尾，前面还有别的字符（Windows 上不能含 `:`，那会指向另一个文件的数据流）。这一条正向规则取代逐个列举的保留名：SQLite 的附属文件名以 `-journal`、`-wal`、`-shm` 或 `-mj` 加九位十六进制结尾，本协议的以 `.lock`、`.partial` 结尾，临时文件（在 `.partial` 目录里）是 `partial-` 加 32 位十六进制及 SQLite 的附属后缀；这些结尾都是 ASCII，并且与 `.sqlite3` 在某个从末尾数起的位置上不同、两个字符也不是同一字母的大小写（最后一个字符 `3` 对 `l`、`m`、`k`，或倒数第八个 `.` 对十六进制数字）。大小写折叠与规范化把每个 ASCII 字符映射为一个字符，两个 ASCII 字符只有在是同一字母的大小写时才会相等，所以以 `.sqlite3` 结尾的名字在任何文件系统上都不等价于它们（第二轮 R2-01、第三轮 R3-01；`library.sqlite3-ſhm` 在折叠大小写的 ext4 上就是 `-shm`）。
- 时限与限制：时限只管复制语句，是协作式的，语句结束之后不再按时限中断；表示不了的时限或等锁时间视为不设；两者都不限制整次备份的时长。等锁每 50 毫秒轮询一次并检查取消，打开锁文件与调度另算。打断不了、取消只在之后的检查点生效的：SQLite 的忙等（忙等超时是累计睡眠的预算，不是钟表时间；这段睡眠计入时限）、关闭连接（它是资料库最后一个连接时，不论在哪个进程，会做 WAL 检查点）与发布前后的文件操作。复制读同一个快照期间，其他连接的写入积在 `-wal` 里，复制结束后才能回收。协议假定目标目录与临时目录只有运行备份的用户能写，别的程序放进临时目录、名字像临时文件的文件会被当作残留；每次调用一个线程，并发数由调用方限制（CLI 只起一个）。
- 取消：`BackupCancel` 由调用方设置，备份在下一次检查时停下，调用方仍等待它报告实际结果；丢弃 future 也会设置取消。CLI 的 Ctrl-C 设置取消后等待结果，所以“已取消”只在确实没有写入时报告。
- CLI：`rssr-cli backup <文件>.sqlite3 [--timeout <秒>]`（默认 600 秒）。开始备份之前就注册 Ctrl-C 的监听（Unix `signal(SIGINT)`、Windows `windows::ctrl_c()`，二者在构造时注册），注册失败即报错、不开始备份（第四轮 R4-04）；Ctrl-C 先设置取消再打印提示；结果行的写出失败不改变退出码（第三轮 R3-03）。不读出站策略、不经存储层打开资料库；数据目录里没有 `library.sqlite3` 时报错。tokio 加 `signal` 功能（`signal-hook-registry` 已在锁文件里，锁文件不变）。
