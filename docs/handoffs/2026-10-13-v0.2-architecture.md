## 关键变更

### 已确认的决定

- 正式 Web：资料库在服务器上，登录后任何设备获得完整功能；服务器上的 CLI 共用这份资料库。
- 演示站：GitHub Pages，浏览器内存 SQLite + 同一套仓储代码，不保存，刷新即重置，网络禁用。
- 存储：所有平台一个 `library.sqlite3`；逐步从 sqlx 迁到 rusqlite（迁移期 0.39，删除 sqlx 后 0.40）；新基线吸收未发布的 0008 / 0009。
- 兼容性：不兼容旧进程、旧浏览器存储与降级；保留 v0.1.0–v0.1.23 本机资料库的单向导入。
- GUI 与 CLI 仍是两个程序（见 `cli-gui-distribution.md`）。
- 版本：`v0.2.0`。

### 产品边界的表述

“不做文章库同步”保持不变；新增“资料库”定义：每个资料库独立，资料库之间只交换配置。服务器端 Web 是多个入口访问同一资料库，不是同步。

### 阶段 A 入口验证（2026-10-13）

一次性验证 crate，不入库，位于 `target/audit-20261009/spike-sqlite/`。结构：目标无关的同步 SQL 核心（`core.rs`）、两端各一个执行器（`executor.rs`）、与 `rssr_domain::FeedRepository` 同形的 `async_trait` 仓储（`repo.rs`）、两端共用的用例（`cases.rs`）。依赖：`rusqlite =0.39.0`（`bundled`、`cache`、`functions`、`hooks`），原生另加 `sqlx 0.9` 与 `libsqlite3-sys 0.37`，wasm 固定 `wasm-bindgen =0.2.126`、`js-sys =0.3.103`、`wasm-bindgen-test =0.3.76`。

共用的 6 个用例：事务出错整体回滚；错误映射为不含 SQL 文本的分类；`fold_for_search` 注册为 SQL 函数，加 `json_each` 订阅过滤，结果与 `rssr_domain::search` 的多文字用例一致；期限到达时语句在引擎内中断，连接随后可用；任务遗留的事务在交还前回滚；经 `Arc<dyn FeedRepository>` 读写。

| 环境 | 命令 / 方式 | 结果 |
|---|---|---|
| Windows 原生（Rust 1.99） | `cargo test`（独立 target 目录） | 10 passed：6 个共用用例、引擎基线、调用方取消后连接仍被占用（下一任务得到 `Busy`）、`InterruptHandle` 中断、sqlx 与 rusqlite 读同一文件 |
| Linux 原生（WSL Debian，rustc 1.97） | `cargo test --locked --test native`（WSL 内独立 target 目录） | 10 passed |
| wasm32，Node 24.21 | WSL Debian（rustc 1.97 + clang 19.1.7）构建，Windows 上 `wasm-bindgen-test-runner` 0.2.126 运行 | 8 passed：6 个共用用例、引擎版本、内存 VFS 上的命名库 |
| wasm32，Chrome 155 | 同上，加 `--features browser`，ChromeDriver 155.0.8059.39 | 8 passed |
| wasm32，Windows 构建 | Rust 1.99 + NDK 28.2 自带 `clang.exe` / `llvm-ar.exe`，Node 运行 | 8 passed |
| Android aarch64 | NDK 28.2，`cargo build --tests --target aarch64-linux-android --locked` | 编译与链接通过；未在设备上运行 |

变异检查（原生）：去掉执行器的回滚清理、在进入阻塞线程前释放准入许可、把 `fold_for_search` 换成恒等函数，各自只让对应的一个用例失败；还原后 10 passed。

实测事实：

- 锁文件只有一个 `libsqlite3-sys`（0.37.0），被 rusqlite 0.39.0 与 sqlx-sqlite 0.9.0 共用；运行时两者的 `sqlite_source_id()` 相同。“迁移期间 rusqlite 0.39 与 sqlx 0.9 共存”成立。
- 原生引擎：SQLite 3.51.3，source id `2026-03-13 10:38:09 737ae4a3…`，`THREADSAFE=1`，页大小 4096。
- wasm 引擎：SQLite 3.53.0，source id `2026-04-09 11:41:38 4525003a…`，`THREADSAFE=0`，页大小 8192；`:memory:` 的日志模式为 `memory`，内存 VFS 上的命名库为 `delete`。两端版本不同，共享用例在两端结果一致。
- wasm 构建需要带 WebAssembly 后端的 clang 与 `llvm-ar`：Windows 上没有独立的 LLVM，NDK 自带的 clang 可用（`--print-targets` 含 wasm32），无需新装工具。

推论（未单独测试）：`sqlite3_interrupt` 只作用于当时正在执行的语句，因此期限的可靠执行放在 progress handler 里，`InterruptHandle` 只用于提前中断。

未覆盖：macOS 原生运行、Android 设备运行（属于阶段 A 完成门禁）；`serialize`（演示站不保存，暂不需要）；wasm 包体积与启动时间（阶段 D 门禁）。
