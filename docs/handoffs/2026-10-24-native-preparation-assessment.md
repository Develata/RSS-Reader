## 关键发现与候选变更

### 当前已确认的边界

- 目录的手动浏览、展开集合、恢复跟随与版本检查，已经由 Rust 管理。
- 下拉刷新距离、方向限制、触发阈值与释放动作已经在 Rust；JS 仍保存上一触点位置，并根据手指方向和嵌套滚动区域判断本次手势是否可用于刷新。
- 阅读位置保存、锚点恢复、两秒恢复窗口与用户输入取消恢复均已在 Rust，但策略、运行期保存集合与 Dioxus 异步生命周期集中在同一文件。
- 图片查看器的 DOM 焦点、原生对话框、同步取消默认事件以及实际滚动属于当前浏览器适配职责。不能只为减少 JS 行数把这些操作搬到异步桥接另一端。

### 候选 1：下拉刷新手势规则收口到独立 Rust 模块

- 在现有页面模块内抽出纯 Rust 手势状态，输入为触摸事实，输出为显示阶段与是否请求刷新。
- Rust 统一保存触点历史，并判断手势方向、控件/文字选择排除、嵌套滚动消费、取消与释放；保留当前 80px 阈值及刷新中禁止重复触发的语义。
- JS 负责监听、DOM 遍历与测量。考虑用两个固定大小的几何摘要表示嵌套区域是否还有向上/向下滚动空间，避免每帧通过桥接发送整份祖先几何数组。
- Dioxus 组件只管理生命周期、订阅显示阶段及调用现有 `shell.manual_refresh()`。
- 风险：双方向摘要可能比现有单方向短路多读取祖先；应评审这个代价，并用真实触摸回归检查方向反转、顶端、嵌套区域、文字选择和取消。此项不预先宣称性能提升。

### 候选 2：阅读位置控制器与 Dioxus 生命周期分离

- 在 `ui/reading_position/` 内增加普通 Rust 控制器，集中管理保存位置、当前访问、恢复窗口与命令计算。
- 用明确的事件类型替代钩子内部的字符串条件；保持现有序列化字段和事件名称兼容。
- 外层继续负责 `document::Eval` 的建立/释放、Android 返回前的捕获，以及现有 `remembered_page()` 调用入口。
- 保持只在导航等操作边界捕获位置，不引入持续滚动时的正文扫描；保持同页锚点优先、锚点失效退回像素位置、新文章从顶部开始与输入立即停止恢复。
- 为同一事件序列建立纯 Rust 测试，覆盖页码不匹配、访问切换、捕获、恢复超时与迟到事件。
- 收益是让未来原生控件复用已有策略，并能脱离 Dioxus 测试；这是模块化，不是把已在 Rust 的规则再次计算为迁移成果。

### 候选 3：目录状态机独立成纯 Rust 子模块

- 将目录状态、事实校验、状态转移与命令生成抽到 `directory/` 子模块，外层保留 presenter 身份判断、Dioxus signal、页面动作派发和桥接生命周期。
- 保留手动浏览不被动拉回、主列表真实滚动恢复跟随、仅展开当前路径、同页定位保留勾选等既有约定。
- 不改变 JS 的测量、真实用户输入归因、消息合并、渲染确认和实际滚动。本轮不重做这套涉及时序的适配协议。
- 保留全查询结果的目录投影；目录浏览不能引发文章重新查询或重新分组，也不能以模块化为由复制整个 presenter。
- 该项优先级低于前两项：现有核心规则已在 Rust，只有独立测试与复用边界的收益值得其改动成本时才纳入本轮。

### 共同约束

- 保持现有七个 crate 与 facade/session → `UiCommand` → runtime → application/host 边界，不新增 crate、依赖或第二套业务状态。
- 本轮只做前端内部调整，沿用当前视觉、路由、持久化格式和业务结果。
- 不选择或接入新的原生渲染框架，不把 DOM 类型下沉到 application/domain。
- 每项单独验证和提交；一项未通过交互等价验证时，不把后续改动叠上去掩盖问题。
- 现有工作区中的其他 dirty、删除与未跟踪文件保持原样。
